MAT-10: Material → Company Relationship (Implementation Plan)

Self-contained execution plan. Another agent should be able to pick this up cold, run the steps in order, and ship a PR. Every file path is relative to the monorepo root (apps/api, apps/frontend). Read the Pre-flight section first. Companion spec: uis-MAT-10-material-company-fk.html (this file is the plan; that is the spec + decision log). Code blocks below are drop-in starting points grounded in the named precedents — match surrounding style, don’t reformat neighbours.

Overview & Outcome

Replace the free-form manufacturer/distributor attributes on a Material with a real M:N relationship to Company. After this lands:

  • A new MaterialCompany(materialId, companyId, role) join links materials to real Companies; Material.manufacturers / Material.distributors resolve to Company rows.
  • A dry-run-first migration backfills the existing pick-list values into MaterialCompany by resolving names against Company.name, then archives + soft-deletes the legacy attribute data.
  • The list view, material-order line items + PDF, facets, material form, and MCP tools all read/write the new relation instead of the attribute slugs.
  • MAT-0 is unblocked — ManufacturerProduct / DistributorPrice can land on a real Material→Company link.
Two decisions flagged for business review (spec §10) — build against these, confirm before merge:
  • Q3 (no primary): each (material, role) is a flat set; full list shows everywhere (comma-joined). A default/primary supplier, if later wanted, is an additive isPrimary column — nothing in this plan changes.
  • Q4 (migration scope): backfill size depends on how many tenants use the catalogue (current read: most don’t). Build the dry-run tooling now; the production commit run is gated on that review. Schema/code steps are independent of it.

1.1 Enum convention — follow ApprovalStatus

An API enum is a three-part set, not just a Prisma enum, and the values are PascalCase (like ApprovalStatus’s InReview / Approved — not SCREAMING_CASE). Mirror ApprovalStatus (defined in apps/api/src/types/Timesheet.types.ts): the Prisma enum above, plus a TS const-array with a derived union type that model / resolver / MCP code imports and validates against:

// apps/api/src/types (e.g. Material.types.ts) — mirrors `approvalStatuses`/`ApprovalStatus`
export const materialCompanyRoles = ["Manufacturer", "Distributor"] as const;
export type MaterialCompanyRole = (typeof materialCompanyRoles)[number];

export interface IMaterialCompany {
    id: string;
    materialId: string;
    companyId: string;
    role: MaterialCompanyRole;
    note: string | null;
    isArchived: boolean;
    isDeleted: boolean;
}

The const-array is the single source of truth — import it, never re-type the values (that’s the whole point of the pattern). Two import sites:

  • Model modelFields: { name: "role", type: "string", options: { enums: [...materialCompanyRoles] } } — precedent models/TimeSheetRecord.ts:284 (enums: [...approvalStatuses]).
  • GraphQL typeDef: interpolate, don’t hand-list — enum MaterialCompanyRole { ${materialCompanyRoles.join("\n")} } — precedent graphql/models/TimeSheetRecord.ts:37–38 + EquipmentTimeEntry.ts:17.

The Prisma enum column (role MaterialCompanyRole) and the const-array carry the same PascalCase values and stay in lockstep; codegen emits a matching GraphQL enum in the generated types, as it does for ApprovalStatus.

2.2 Dry-run report (run + review BEFORE editing the migration)

Read-only. Produces the CSV the spec describes and answers Q4 (how much data actually exists per tenant). No writes.

// apps/api/scripts/mat10-migration-dryrun.ts
import prisma from "../src/models/_prismaClient";

const SLUGS = ["manufacturer", "distributor"] as const;

async function main() {
    for (const slug of SLUGS) {
        const attr = await prisma.materialAttribute.findFirst({ where: { slug }, select: { id: true } });
        if (!attr) { console.log(`${slug}: attribute not present in this tenant — nothing to migrate`); continue; }

        // distinct picked values (mav.value = MaterialAttributeListValue.id) + how many materials use each
        const rows = await prisma.$queryRaw<Array<{ name: string; materials: bigint }>>`
            SELECT malv.name AS name, COUNT(DISTINCT mav.materialId) AS materials
            FROM MaterialAttributeValue mav
            JOIN MaterialAttributeListValue malv ON malv.id = mav.value
            WHERE mav.materialAttributeId = ${attr.id} AND mav.isDeleted = false
            GROUP BY malv.name`;

        for (const r of rows) {
            const exact = await prisma.company.findFirst({
                where: { name: { equals: r.name }, isDeleted: false }, select: { id: true }
            });
            const action = exact ? "EXACT" : "CREATE"; // fuzzy review is a manual pass over CREATE rows
            console.log([slug, r.name, exact?.id ?? "—", action, Number(r.materials)].join("\t"));
        }
    }
}
main().finally(() => process.exit(0));
Gate the commit on a signed-off CSV. Exact matches auto-resolve; everything else defaults to CREATE (conservative — never fuzzy-fold supplier A into B). The fuzzy-review pass (a human eyeballing CREATE rows for near-duplicates) happens here, before commit.

INSERT IGNORE INTO `MaterialCompany`

// apps/api/src/models/MaterialCompany.ts
import prisma from "./_prismaClient";
import type { FullModel, ICompany, IField, IMaterialCompany, MaterialCompanyRole } from "../types";
import { materialCompanyRoles } from "../types";
import { BaseAuditableModel } from "./base/_BaseAuditableModel";
import { BadRequestError } from "../errors";

class MaterialCompany extends BaseAuditableModel<IMaterialCompany> {
    public name = "MaterialCompany";
    public name_plural = "MaterialCompanies";

    protected prisma = prisma.materialCompany;
    protected modelFields: IField<IMaterialCompany>[] = [
        { name: "materialId", type: "string" },
        { name: "companyId", type: "string" },
        { name: "role", type: "string", options: { enums: [...materialCompanyRoles] } },
        { name: "note", type: "string", options: { isNullable: true } }
    ];

    // Join row owns no children.
    public archiveChildren(): Promise<void> { return Promise.resolve(); }
    public restoreChildren(): Promise<void> { return Promise.resolve(); }
    public deleteChildren(): Promise<void> { return Promise.resolve(); }
    public async getRelatedDeleteCount(): Promise<Record<string, number>> { return {}; }

    public async validatePayload(input: Partial<IMaterialCompany>): Promise<void> {
        const { materialId, companyId, role } = input;
        if (!materialId || !companyId) throw new BadRequestError("materialId and companyId are required.");
        if (!materialCompanyRoles.includes(role as MaterialCompanyRole)) {
            throw new BadRequestError(`role must be one of: ${materialCompanyRoles.join(", ")}`);
        }
        const material = await prisma.material.findFirst({ where: { id: materialId, isDeleted: false }, select: { id: true } });
        if (!material) throw new BadRequestError(`materialId ${materialId} does not resolve.`);
        const company = await prisma.company.findFirst({ where: { id: companyId, isDeleted: false }, select: { id: true } });
        if (!company) throw new BadRequestError(`companyId ${companyId} does not resolve.`);
    }

    // The unique index on (materialId, companyId, role) ignores isDeleted, so a
    // create after a delete hits the constraint — revive the soft-deleted row instead.
    public async attachOrRevive(
        input: { materialId: string; companyId: string; role: MaterialCompanyRole; note?: string | null },
        currentUserId: string
    ): Promise<FullModel<IMaterialCompany>> {
        await this.validatePayload(input);
        const stale = await this.prisma.findFirst({
            where: { materialId: input.materialId, companyId: input.companyId, role: input.role, isDeleted: true }
        });
        if (stale) {
            return this.editItem(stale.id, {
                isDeleted: false, isArchived: false, note: input.note ?? null
            } as unknown as Partial<FullModel<IMaterialCompany>>, currentUserId);
        }
        return this.createItem(input as unknown as Partial<FullModel<IMaterialCompany>>, currentUserId);
    }

    // Flat set per (material, role): detach removed, attach/revive added. No order, no primary (Q3).
    public async syncForMaterial(
        materialId: string,
        role: MaterialCompanyRole,
        companyIds: string[],
        currentUserId: string
    ): Promise<void> {
        const existing = await this.prisma.findMany({
            where: { materialId, role, isDeleted: false },
            select: { id: true, companyId: true }
        });
        const desired = new Set(companyIds);
        for (const row of existing) {
            if (!desired.has(row.companyId)) await this.deleteItem(row.id, currentUserId);
        }
        const have = new Set(existing.map((r) => r.companyId));
        for (const companyId of companyIds) {
            if (!have.has(companyId)) await this.attachOrRevive({ materialId, companyId, role }, currentUserId);
        }
    }

    public async forMaterial(materialId: string): Promise<(IMaterialCompany & { Company: ICompany })[]> {
        const rows = await this.prisma.findMany({
            where: { materialId, isDeleted: false, isArchived: false },
            include: { Company: true },
            orderBy: { Company: { name: "asc" } }
        });
        return rows as unknown as (IMaterialCompany & { Company: ICompany })[];
    }

    public async companiesForRole(materialId: string, role: MaterialCompanyRole): Promise<ICompany[]> {
        const rows = await this.forMaterial(materialId);
        return rows.filter((r) => (r as unknown as { role: MaterialCompanyRole }).role === role).map((r) => r.Company);
    }
}

export { MaterialCompany };

export const MaterialCompanyResolvers: IModelResolverConfig<IMaterialCompany> = {

        type MaterialCompany {
            id: ID
            materialId: String
            companyId: String

async function resolveCompanyIdOrPrompt(name: string, ctx): Promise<{ companyId?: string; prompt?: string }> {
    const { companies } = await new Company().getList({ /* search name, limit 5 */ }, ctx.userId);
    const exact = companies.find((c) => c.name.trim().toLowerCase() === name.trim().toLowerCase());
    if (exact) return { companyId: exact.id };
    // No match — DO NOT auto-create. Return a prompt for the caller/user to confirm.
    return { prompt: `No company named "${name}" found${companies.length ? ` (closest: ${companies.map(c => c.name).join(", ")})` : ""}. ` +
                     `Confirm creating it, or pass an existing companyId.` };
}
Search → confirm → create; never silent. On no-match, the tool returns the prompt (does not create). Only on explicit user confirmation does it create the Company (untyped) and link it. Do not recreate the old MaterialAttributeValue path.
