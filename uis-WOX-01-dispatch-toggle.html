Dispatch Board V0 — Calendar Toggle

Adds a "Dispatch" view toggle alongside the existing Calendar view on /scheduling/calendar, scoped to Job.jobType = "WORK_ORDER". V0 is just the toggle + a filtered WO list. Full Kanban dispatch board ships in 1.34 (see WOX-16).

Status: Concept Effort: ~1-2d Extends: WO-9a · scheduling/calendar Master ref: #25

1. Where this lives in the app

Page / route: apps/frontend/src/pages/scheduling/calendar.tsx
Components touched: apps/frontend/src/components/Settings/ScheduleSettings.tsx (toolbar pattern), calendar toolbar (path TBD — verify)
New components: <DispatchToggle />, <DispatchListV0 /> (path TBD)
API surface: GraphQL — reuses existing scheduled-event queries with a jobType: WORK_ORDER filter; no new resolvers

The existing calendar lives at scheduling/calendar.tsx. V0 adds a segmented toggle in the page toolbar — Calendar (default) and Dispatch (NEW). When Dispatch is selected, the same page renders a stripped-down list of this-week's scheduled work orders. No new GraphQL queries — we filter the same scheduled-event query by jobType.

Persistence uses localStorage per userId so a dispatcher who lives in Dispatch view doesn't get bounced back to Calendar every session. Per-instance default lives in InstanceSetting (default Calendar; service-co instances flip to Dispatch).

Desktop calendar page with a segmented toggle in the toolbar. When Dispatch is selected, a banner explains the V0 scope and a filtered WO list renders below.

3. Key decisions for Emma + Corey to discuss

D1 Should the Calendar / Dispatch toggle persist per-user?
Recommended: Yes — store last selection in localStorage keyed by userId. Dispatchers live in Dispatch view; project managers stay on Calendar. No new server-side preference needed for V0.
D2 What's the default view for service-co customers vs project-co?
Recommended: Per-instance setting on InstanceSetting.defaultSchedulingView. Default CALENDAR for back-compat; Thermogenics-class instances flip to DISPATCH. Per-user override still wins.
D3 Should non-WO Jobs render in the Dispatch view?
Recommended: No — WO-only. Dispatch is a high-volume tactical view; mixing project Jobs muddies it. Calendar remains the unified view. Filter at query level via jobType: WORK_ORDER.
D4 V0 placeholder copy or a real filtered list?
Recommended: Real filtered list now. A dispatcher hitting an empty placeholder feels broken; the list view delivers immediate value and gives us real customer signal on what V2 should actually do (per master plan, "proves the WO scheduling loop works end-to-end").
D5 Does this ship together with the calendar filter fix (item #22)?
Recommended: Yes — bundled PR. The filter fix (in-progress WOs not rendering) is the prerequisite for the Dispatch list to look correct. Both ~1d each, single review.
