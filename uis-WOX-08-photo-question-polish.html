Photo Question Polish (Mobile Forms)

The "photo" question type on mobile forms feels half-finished — small thumbnails, awkward delete, no captions, no required-min count. Tighten the UX so techs actually use it instead of texting photos to admins.

Status: Concept · polish Effort: +1-2d on WO-8 Extends: WO-8 · F01 Master ref: #24

1. Where this lives in the app

Mobile renderer (today): apps/mobile/src/components/Forms/SafetyFormQuestionAndAnswers/QAForm.tsx — PHOTO question handled inline (lines 689–801). Verified: PHOTO is one of the question types in the QAForm switch, but it does not have a dedicated component file.
Mobile component (proposed): apps/mobile/src/components/Forms/SafetyFormQuestionAndAnswers/PhotoQuestion.tsx (path TBD — to be extracted from QAForm.tsx as part of this polish)
Form builder (desktop): apps/frontend/src/components/Forms/QuestionnaireForm/QuestionnaireAddEditForm.tsx — verified. Photo question config will gain new fields here.
New components: PhotoQuestionConfig.tsx (sibling to existing QuestionTypes/*.tsx in QuestionnaireForm folder)
API surface: GraphQL — SafetyFormQuestion input gains photoMin, photoMax, captionMode, allowGalleryImport, storeExif fields

Today the PHOTO question type lives inline inside the giant QA form switch — no captions, small thumbnails, no min/max enforcement, no per-question UX configurability. This polish extracts the renderer, adds the missing affordances, and exposes the new options in the form builder so each form author can dial photo behaviour per question.

3. Key decisions for Emma + Corey to discuss

D1 Default to camera or gallery on tap "+ Add photo"?
Recommended: Action sheet — Camera / Gallery / Cancel. Camera-only is faster but excludes the "I already shot it on my personal photo app" workflow techs use today. Action sheet is one extra tap and unblocks both flows.
D2 Captions: optional, required, or off per question?
Recommended: Configurable per question, default off. Forces form authors to make a deliberate choice. HIRA-class forms will turn captions on; routine "before/after" photo questions can stay caption-less.
D3 Max photos: hard cap?
Recommended: Configurable, default 10, hard ceiling 25. Prevents pathological cases (50-photo question = 200MB upload from the field) without crippling legitimate use cases like a comprehensive condition survey.
D4 EXIF / GPS metadata stored?
Recommended: Yes — surface GPS in form review for HIRA-class forms. Solves "was this photo taken on the actual site?" auditing question. Strip EXIF on customer-facing PDFs (privacy). Configurable per question so non-safety forms can opt out.
D5 Compress server-side?
Recommended: Yes, max 2MB stored, original kept for 30 days then purged. Massive storage win without losing quality for the field-evidence use case. The 30-day window covers the typical dispute / RFI lookback period.
