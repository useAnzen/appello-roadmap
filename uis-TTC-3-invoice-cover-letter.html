Invoice Cover Letter / Transmittal Templates

A new kind of DocumentTemplate built for invoice cover letters. Write the letter once, drop in merge tags ({{invoiceNumber}}, {{amount}}, {{dueDate}}, {{contactFirstName}}), assign a default per customer. Every time TTC-2 sends an invoice, the cover letter renders with real values and rides along — either as the email body or as a second PDF.

Customer drivers: Mak (transmittal letters), Owens, Rival Effort: 2 days · 1 engineer Existing infra: DocumentTemplate + merge-tag engine (proven on quotes/COs)

1. Why this matters

Most billing admins paste the same boilerplate cover letter into every invoice email — the same greeting, the same description, the same "please remit to…" closing — but with a different invoice number, amount, and date filled in by hand each time. That copy-paste workflow is error-prone and unprofessional when something gets missed.

"We need options for transmittal letters that auto-generate based on client info, then send the invoice and letter to the client's email." — Mak Surveying (May 5, 2026 commitment call)

Appello already has the DocumentTemplate system — used today for estimate cover letters, change order forms, and a proven merge-tag engine (EstimateChangeOrderRecord.mergeTags). TTC-3 is a small extension: add a new kind for invoice cover letters, define the merge-tag set for invoices, and let admins set a default per customer. The work is small but the visible polish is high — every send now looks branded and professional with zero per-bill effort.

2. Who this is for

  • Office managers / owners who set up the templates once during onboarding and rarely touch them again.
  • Billing admins who get the benefit on every send — letter is just there, filled in correctly.
  • Customers who receive a cleaner, more professional-looking email with the invoice attached.
  • Onboarding consultants at Appello who can ship a customer with their existing letterhead/wording in ~30 minutes.

3. User stories

As an office manager
I want to create an invoice cover letter template with our company tone, so every invoice we send sounds like us.
As an office manager
I want to insert merge tags like {{customerName}} and {{amount}}, so the letter personalizes itself for every recipient.
As an office manager
I want to preview the merged letter against a real bill before saving the template, so I can spot typos and bad merge tags.
As an office manager
I want to set a default cover letter per customer, so different customers can get different letters (e.g., one for muni clients, one for private developers) without me thinking about it on every send.
As a billing admin
I want the right cover letter to be auto-selected when I open the Send modal (TTC-2), so I can hit Send without picking from a list every time.
As a billing admin
I want to override or skip the cover letter for a one-off bill, so a non-standard situation doesn't force me to send the wrong letter.

4. A day in the life: today vs. tomorrow

Mary is sending out 30 invoices for the month. Each one needs a cover letter to satisfy the developers' AP departments.

Today (no TTC-3)

  1. Open Word → open last month's "transmittal-template.docx"
  2. Find/replace the invoice number (sometimes misses one)
  3. Find/replace the dollar amount
  4. Update the date
  5. Save as PDF, name it carefully
  6. Switch to Outlook, attach both the cover letter PDF and the invoice PDF
  7. Type the email body
  8. Send
  9. Pray you didn't paste yesterday's number into today's letter (this happens)
  10. Repeat 29 times
~5 min per bill · ~150 min batch · occasional embarrassing typos

Tomorrow (with TTC-3 + TTC-2)

  1. Hit Send on the bill (TTC-2)
  2. Modal opens — body is the cover letter, fully merged with this bill's data
  3. Confirm or tweak → Send
  4. Repeat 29 times
~15 sec per bill · ~8 min batch · zero merge typos by construction

6. What's in / out of scope

✓ In scope (v1)

  • New kind field on DocumentTemplate with InvoiceCoverLetter as the v1 enum value
  • "Invoice Cover Letters" tab on Settings → Document Templates
  • ~12 invoice merge tags (invoice #, amount, dueDate, periodStart/End, customer, contact first/full, job #, sender, instance, PO)
  • TipTap-based editor with merge-tag insertion (existing component, just a new merge-tag set)
  • Preview against any real bill (rendered HTML output)
  • Per-customer default via new Company.defaultInvoiceCoverLetterTemplateId
  • Instance-level fallback: if customer has no default, use the instance default
  • TTC-2 Send modal auto-loads the resolved default and merges on open
  • One-click "skip cover letter" override per send
  • Permission-gated template editing (reuse existing documentTemplate.edit)

✗ Out of scope (later)

  • AI drafting of letter text (EPI proof-of-concept exists but later)
  • Multi-language template variants (later)
  • Reminder-letter sub-kinds — handled by TTC-4 with its own kind values
  • Letterhead / image upload inside the template (use existing letterhead pipeline)
  • Conditional content blocks ("if {{poNumber}} then…")
  • Template versioning / approval workflows
  • Per-job override of the customer default (later if asked)

7. Decisions needed

D1 · Cover letter delivery: email body, separate PDF attachment, or merged PDF?
Three options: (a) inline as the email body itself; (b) separate PDF attachment alongside the invoice PDF; (c) merged into a single PDF (cover page + invoice page). Recommend (a) email body for v1, (b) optional PDF attachment as a setting. Merged PDF is post-v1 — needs pdf-worker work.
D2 · Default cascade order
Recommend job-level override → customer default → instance default → none. Job-level isn't in v1 scope but the cascade is built so adding it later is one new field.
D3 · Merge tag missing-value behavior
If a tag has no value (e.g. customer has no PO number), recommend rendering as empty string with a yellow warning in the preview panel during design-time. At send-time, render empty without a warning (the user already saw the preview).
D4 · Should an instance start with a built-in "Standard Transmittal" template?
Recommend yes. Seed every instance with a sensible default template on enable so the customer doesn't have to write the first one from scratch.

8. Acceptance criteria

  1. "Invoice Cover Letters" tab appears under Settings → Document Templates for users with documentTemplate.edit.
  2. Creating a template lets the user enter a name and rich-text body in the existing TipTap editor.
  3. The merge-tag palette lists all v1 invoice merge tags; clicking one inserts a chip at the cursor.
  4. Preview lets the user pick any non-deleted JobBill and renders the merged HTML.
  5. Saving a template creates a DocumentTemplate row with kind = InvoiceCoverLetter.
  6. On a Customer detail page, a new "Default invoice cover letter" dropdown selects from the library.
  7. Instance Settings has a global "Default invoice cover letter (instance fallback)" dropdown.
  8. When TTC-2's Send modal opens for a bill, it resolves the cover letter via cascade (customer → instance → none) and pre-fills the body.
  9. The user can switch the cover letter or skip it for the current send without changing the customer default.
  10. Missing merge tag values render as empty strings with no error in production sends.
  11. Soft-deleting a template that's a customer default falls back to the instance default; sends still work.
  12. A new instance is seeded with one built-in "Standard Transmittal" template (per Decision D4).

Engineering notes

Data model

Two small additions: a kind enum on the existing DocumentTemplate, and a default-template foreign key on Company.

enum DocumentTemplateKind {
  Generic
  QuoteCoverLetter
  ChangeOrderForm
  InvoiceCoverLetter   // NEW
  ReminderLetter       // reserved for TTC-4 — see that spec
}

model DocumentTemplate {
  // ... existing fields ...
  kind  DocumentTemplateKind @default(Generic)   // NEW; Generic for back-compat
}

model Company {
  // ... existing fields ...
  defaultInvoiceCoverLetterTemplateId String?            @db.VarChar(21)
  DefaultInvoiceCoverLetterTemplate   DocumentTemplate?  @relation("CompanyDefaultInvoiceCoverLetter", fields: [defaultInvoiceCoverLetterTemplateId], references: [id])
}

// Instance-level fallback already lives in InstanceSettings or similar — add a field there
model Instance {
  // ... existing fields ...
  defaultInvoiceCoverLetterTemplateId String? @db.VarChar(21)
}

Model methods (in apps/api/src/models/JobBill.ts + DocumentTemplate)

  • JobBillModel.getMergeTagValues(jobBillId) — pure read; returns the typed dictionary used by all merge consumers.
  • DocumentTemplateModel.renderInvoiceCoverLetter(templateId, jobBillId, userId) — runs Mustache-style merge over bodyHtml using getMergeTagValues; returns rendered HTML.
  • JobBillModel.resolveCoverLetter(jobBillId) — implements the cascade (job → customer → instance → none).

Frontend touch points

  • DocumentTemplatesPage.tsx — new "Invoice Cover Letters" tab; reuses the existing template list/editor components scoped to kind = InvoiceCoverLetter.
  • InvoiceCoverLetterEditor.tsx (new) — thin wrapper around the existing TipTap editor with the invoice merge-tag palette and a preview pane.
  • CompanyBillingSettingsForm.tsx — adds the "Default invoice cover letter" dropdown.
  • InstanceSettings → Billing — adds the instance-level fallback dropdown.
  • SendInvoiceModal.tsx (TTC-2) — calls resolvedInvoiceCoverLetter on open and uses its merged HTML as the default body.
