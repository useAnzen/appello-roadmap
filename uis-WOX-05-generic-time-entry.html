Generic Time Entry — Placeholder Labor Lines

Office users can book labor capacity on a WO before specific techs are assigned ("2 × Journeyman, 4 hrs each"). Placeholders auto-resolve to real LaborLine rows tied to specific userId + date when the dispatch flow assigns techs. Honors the user-first time/labor allocation rule — placeholders never appear in timesheets.

Status: Concept Effort: ~2d Extends: WO-2 · uis-LEM-1 Master ref: #15

1. Where this lives in the app

WO create / detail: apps/frontend/src/pages/jobs/[id]/index.tsx (jobType=WORK_ORDER) — extends Line Items tab labor block (path TBD — verify, sits with uis-20c-2-line-item-editors.html spec)
Timesheet integration: apps/frontend/src/pages/scheduling/calendar.tsx + dispatch resolve modal; no change to uis-12-leave-timesheet.html surface (placeholders never write timesheets until resolved)
New components: <PlaceholderLaborRow />, <ResolvePlaceholderModal />
API surface: GraphQL — LaborLine.kind: PLACEHOLDER | ACTUAL enum, LaborLine.userId nullable when kind = PLACEHOLDER, LaborLine.tradeLevelId required, LaborLine.quantity (head count); resolvePlaceholderLaborLine(lineId, assignments: [{userId, date, hours}]) mutation

Placeholders are WO-side data, not timesheet data. They never feed payroll or appear on a user's timesheet. Resolution happens via the dispatch flow (V0 today, full Kanban in WOX-16): the dispatcher assigns techs + dates, the system creates real ACTUAL labor lines tied to specific userId+date, and the placeholder is marked resolved.

3. Key decisions for Emma + Corey to discuss

D1 Do placeholder lines flow into estimates / invoices before resolution?
Recommended: Yes for estimates only (billable rate × placeholder qty × hrs gives a clean upfront estimate). Never for actual billing — invoices only include resolved ACTUAL rows. Prevents billing the customer for a tech that never showed up.
D2 What triggers resolution?
Recommended: Two paths. (a) Scheduled crew check-in via the dispatch flow auto-resolves the matching placeholder. (b) Manual "Assign to placeholder" action in the WO line items table. Both end at the same mutation.
D3 What happens to over/under hours on resolution?
Recommended: Actual hours win — placeholder is discarded. Audit log captures placeholder estimate vs actual delta for post-mortem reporting. No re-billing needed because invoices use ACTUAL only.
D4 Timesheet rollup — placeholder vs actual?
Recommended: Actual only. Placeholders never appear on a user's timesheet, in payroll exports, or in uis-12-leave-timesheet rollups. This preserves Emma's invariant ("timesheets need dates and users") and the workspace user-first-allocation rule.
D5 Trade-level mismatch on resolution (e.g., placeholder Journeyman → actual Apprentice)?
Recommended: Warn + allow override per WOX-10 (Trade Level Override on WO). Constrained to other levels within the user's current employee agreement. Cost rate uses the actual user; bill rate uses the WO's defined trade level — preserves margin clarity.
