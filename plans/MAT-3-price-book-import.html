MAT-3: Price Book Import (Implementation Plan)

Self-contained execution plan. File paths are relative to the monorepo root (apps/api, apps/frontend). Read Pre-flight first. Companion spec: uis-MAT-3-price-book-import.html. Code blocks are drop-in starting points — match surrounding style.

Overview & Outcome

MAT-3 bulk-loads a distributor’s price book into the existing MaterialAttributePrice source rows (the MAT-0 per-cell cost grid). It is a data-entry accelerator, not a new data model. Two tiers, built behind one pipeline:

  • Tier 1 (this slice’s MVP) — deterministic manual mapper. Upload a normalized CSV/XLSX (one row per SKU) → map columns to price-book fields → preview → commit. Works with no AI.
  • Tier 2 (phased add-on, future paywall) — AI matrix parser. A pluggable front stage that turns a raw 2-D matrix book (pipe-size × thickness grids, 400 tabs) into the same normalized rows Tier 1 consumes. Out of the MVP; architected as a stage, not built now.

Each row resolves match-or-create: match an existing source row / variant by SKU and update its price/discount, or create the Material + variant cell + MaterialCompany link + source row. Discounts in the sheet match-or-create a buy-side Discount (MAT-9). Only one new table: PriceBookImport (an import-job audit log).

Both halves already exist as working code to draw from.
  • Tier-1 engine — useAnzen/csv-import (cloned at appello/csv-import): a model-agnostic import wizard — src/lib/csv-import/{parser,auto-match,transform,duplicate-utils,types}.ts + components/csv-import/ (file-upload → column-mapping → validation → results) + lib/GraphQLConnection.ts. autoMatchColumns() is the fuzzy header→field matcher with confidence scores.
  • Tier-2 IP — Appello-Prototypes/xpipe (cloned at appello/xpipe): catalyst/apps/web/src/lib/cci/parser.ts parsePipeGrid() (diameters=rows, thicknesses=cols, cell=net price/LF) + parsePipeSize/parseThicknessHeader/makeMaterialCode; packages/ai/src/{prompts/extraction,tools/detect-sheet,tools/extract-legend}.ts detect which tab is what product and where the axes are.

Pre-flight (do this first)

Repo & grounding

  • Working repo: the Appello monorepo (useAnzen/application-mono-repo). Branch off the active “Release 1.33” integration branch — confirm with the user.
  • Reference repos (read-only, cloned as siblings): useAnzen/csv-import and Appello-Prototypes/xpipe. Lift logic/approach; do not import them as dependencies (xpipe is a separate catalyst/Bun stack with its own Prisma schema).
HARD PREREQUISITES — MAT-0, MAT-9, MAT-10 must be merged first.
  • MAT-0 ships the MaterialAttributePrice source-row columns (distributorId/manufacturerId/sku/listPrice/discountId/packageQty/…) and widens upsertManyItems dedup to include the source. MAT-3 writes through that exact path.
  • MAT-9 provides the buy-side Discount (direction:Buy + distributorId) a sheet’s discount column maps to.
  • MAT-10 provides MaterialCompany — the create branch must add the distributor link (confirm-then-create), and the source-row write is gated on it.
Material is NOT in the DataModelForm system. csv-import’s generic engine discovers target fields by introspecting a model’s DataModelForm (graphql/models/DataModel/dateModelForms.ts). Material / MaterialAttributePrice have no DataModelForm — the material grid is driven by TableFeed (graphql/models/TableFeed/ConfigureColumnsData/material.ts, read/facet-oriented), and writes go through MaterialAttributePriceModel.upsertManyItems. So MAT-3 reuses csv-import’s engine (wizard, autoMatchColumns, validation, dedup) but supplies an explicit price-book import field schema (Step 1) as the map target — it does not read DataModelForm. Do not try to register Material into DataModelForm.

Step 3 — Import engine (deterministic core, Tier 1)

Goal
parse → auto-match → validate → resolve (match-or-create) → write. The heart of the slice.
Files
src/models/PriceBookImport.ts + src/.../priceBookImport/{parse,match,resolve}.ts NEW; ports from csv-import/src/lib/csv-import/* REUSE

3.1 parse + auto-match (port from csv-import)

Lift parser.ts (CSV/XLSX → {headers, rows}) and auto-match.ts (autoMatchColumns(headers, fields)) verbatim, feeding the Step-1 field schema as fields. Keep transform.ts + duplicate-utils.ts + the typed ValidationResult model.

3.2 resolve each row — match-or-create

// per normalized row, after column mapping
// 1. MATCH by sku (3-way)
//    a. existing source row for this distributor  -> update listPrice/discountId
//    b. existing house-row sku (operator-modeled variant) -> attach/update source row on that cell
//    c. no match -> CREATE
// 2. CREATE branch
//    - find-or-create Material by productName
//    - resolve/create MaterialAttributeListValue per mapped axis -> the variant cell
//    - ensure MaterialCompany(material, distributor, role=Distributor) link (MAT-10 confirm-then-create)
//    - (optional) manufacturer -> MaterialCompany(role=Manufacturer)
// 3. discount column -> match-or-create buy-side Discount (MAT-9) -> discountId
// 4. write the source row via MaterialAttributePriceModel.upsertManyItems(...)

The writer is always upsertManyItems (it dedups on cell+source post-MAT-0, so match-update and create converge through one call). The model-layer MaterialCompany gate runs inside the MAP write — the engine just ensures the link exists first.

Flag — axis resolution from a normalized sheet. Tier 1 requires the axis values to be in mapped columns (e.g. a “Pipe Size” and “Thickness” column). If a sheet has the size embedded in a description string with no axis columns, Tier 1 skips the row with an error (DECIDED) rather than creating a coarse/0-axis material — splitting a description into axes is Tier 2’s job (xpipe’s parsePipeSize/parseThicknessHeader). The skipped rows surface in the error log for the operator to fix the sheet (add axis columns) or wait for Tier 2.

Step 6 — Tier 2: AI matrix parser (phased, pluggable — NOT in the MVP)

Goal
A front stage that turns a raw 2-D matrix book into the normalized rows Step 3 already consumes. Specify now; build later (paywall candidate).
Files
future src/.../priceBookImport/matrix/*; lift from xpipe REF

Architect Step 3 so the normalized-row array is the seam: Tier 1 produces it from a flat CSV via column mapping; Tier 2 produces it from a matrix book via xpipe’s approach, then hands off to the same resolve+write (3.2). Tier 2 pipeline (from xpipe cci + packages/ai):

  • detect-sheet → which tabs are price grids and what product each is (packages/ai/.../tools/detect-sheet.ts).
  • extract-legend → which header row/col are the axes (pipe size / thickness) (tools/extract-legend.ts + prompts/extraction.ts).
  • parse grid → deterministic cell extraction (cci/parser.ts parsePipeGrid + parsePipeSize/parseThicknessHeader/parsePrice); generate a variant code via makeMaterialCode (aligns with MAT-0’s generated SKU / the sku-generator repo).
  • Emit normalized rows → the operator reviews them in the same Step-5 preview → commit.
Gating: Tier 2 is the paywall-able add-on. The Tier-1 wizard ships and works without it; the AI stage appears as an alternate “upload a raw price book” entry that feeds the same review/commit.

Step 8 — Smoke test & acceptance

Manual smoke

  1. Upload a normalized CSV (sku, product, pipe size, thickness, list price, discount) for distributor Crossroads. Map columns (auto-matched). Preview shows ready/error/price-change counts.
  2. Known SKU → its MAP source row’s listPrice/discountId updates. Unknown SKU → new Material + variant cell + MaterialCompany link + source row created.
  3. A discount column creates/links a buy-side Discount and sets discountId.
  4. A row with no SKU errors; the error log is downloadable.
  5. Price-comparison tab on the Crossroads Company page shows old vs new.
  6. With RESTRICT_MATERIAL on, the import surface is hidden.

Acceptance criteria

  • Normalized CSV/XLSX parses; columns auto-match (≥80%) against the price-book field schema and are manually overridable.
  • Known SKU updates its MAP source row; unknown SKU creates Material + variant cell + MaterialCompany link + source row (match-or-create).
  • Discount column match-or-creates a buy-side Discount (MAT-9) and sets discountId.
  • All writes go through MaterialAttributePriceModel.upsertManyItems; the MaterialCompany gate is enforced.
  • Preview shows ready / error / price-change counts with old-vs-new; errors highlighted + downloadable.
  • Import history is viewable per distributor; price comparison shows on the Company detail.
  • Tier 1 works with no AI; the normalized-row seam is in place for Tier 2.
  • Reuses material-pricing write permission (no new permission); honors RESTRICT_MATERIAL.

Downstream & deferred

  • Tier 2 AI matrix parser (paywall candidate) — lift xpipe cci + packages/ai into the normalized-row seam.
  • Tier-1 fallback DECIDED: skip-with-error when a sheet lacks axis columns (Step 3.2). Open: whether to derive the field schema partly from TableFeed material.ts vs hand-author (recommend hand-author — TableFeed is read-oriented).
  • Feeds MAT-5 (priced source rows + package qty for supplier POs) and fast distributor onboarding.
Net new surface: 1 table (PriceBookImport), 1 import-field schema, the resolve/match-or-create engine, a GraphQL preview+import pair, and an in-product wizard ported from csv-import. Everything underneath — source-row upsert, dedup, MaterialCompany gate, discount resolution — is inherited from MAT-0 / MAT-9 / MAT-10.
