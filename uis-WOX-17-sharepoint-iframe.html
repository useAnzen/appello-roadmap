SharePoint Phase 2 — In-App iFrame

Phase 1 (WOX-15) is paste-link → opens new tab. Phase 2 embeds the SharePoint document inside Appello via iframe so users can preview and edit without context-switching. Reuses the same ExternalDocument model with a new provider field; OneDrive and Google Drive ride on the same plumbing. Microsoft Graph OAuth required.

Status: Concept · 1.34 candidate Effort: ~10d (depends on MS Cloud Partner enrollment, 2-4 weeks external) Extends: WOX-15 Master ref: #31 — UIS-DOC-2

1. Where this lives in the app

Pages / routes: Job · Project · WO detail pages — same hosts as WOX-15 (apps/frontend/src/pages/jobs/[id]/index.tsx, etc.)
New components: components/ExternalDocuments/EmbeddedDocViewer.tsx · DocumentSideFlyout.tsx · MicrosoftAuthConnect.tsx (settings page)
Model extension: add provider enum (SHAREPOINT · ONEDRIVE · GDRIVE · OTHER) + embedUrl + lastEditedAt + lastEditedByDisplayName to ExternalDocument
OAuth surface: Microsoft Graph delegated permissions — Files.ReadWrite · Sites.Read.All · per-user delegation initially
Settings page: /settings/integrations/microsoft — connect / disconnect MS 365 account

Side-flyout pattern keeps the user in their Appello context — no new tabs, no lost state. The iframe uses Microsoft's official Office 365 embed URL pattern (?action=embedview) which renders the doc using user's existing SharePoint permissions — no permission shadow.

2. UI Concept

User clicks an external doc on the Job detail → instead of opening a new tab, a side flyout slides in with the SharePoint Word doc rendered inside an iframe (real Office 365 embed). Header shows source · file · last edit metadata.

3. Key decisions for Emma + Corey to discuss

D1 OAuth scope — instance-wide service principal vs per-user delegation?
Recommended: Per-user delegation initially. Simpler permission story (the user only sees what their SharePoint already lets them see), no admin-consent dance for V2 launch, easier to revoke. Service-principal mode becomes a customer-asked enterprise upgrade later.
D2 View-only or full edit?
Recommended: Mirror the user's SharePoint perms — no app-level override. If their SharePoint role allows edit, the iframe edits live. If view-only, the iframe is read-only. Adding an Appello-side override here invents a permission shadow and a support nightmare.
D3 Supported providers in V2?
Recommended: SharePoint + OneDrive at launch (one OAuth, two providers). Google Drive in Q3 (separate OAuth). Box on explicit customer request. Tip-tap revisit (Emma's note re page-break support shipping) is a worth-it 1-day spike before committing to MS Cloud Partner enrollment.
D4 Offline / cache?
Recommended: No. Pure embed, online-only. Caching SharePoint content into Appello creates a sync-conflict and compliance problem we don't want. The embed URL is short-lived; if user goes offline the flyout shows the standard "you're offline" state.
D5 Mobile experience?
Recommended: Deep-link to the provider's mobile app (SharePoint mobile, OneDrive mobile). The iframe pattern doesn't translate to a phone viewport — Office mobile is genuinely better than an embedded Office in a flyout. Tablet falls back to the full desktop iframe.
