Work Order Templates — Save & Load

Pre-built WO templates ("HVAC quarterly service", "Boiler inspection") that pre-fill subject, default forms, line items, and trade levels. Saves dispatch admins from rebuilding the same WO every Tuesday morning.

Status: Concept Effort: ~5-6d Extends: WO-10 · uis-20a-job-type-config Master ref: #27

1. Where this lives in the app

Settings entry: apps/frontend/src/components/Settings/PropertySettings.tsx → new "Work Order Templates" tab (path TBD — verify, mirrors JobSettingsTabs.tsx pattern)
WO create flyout: new "Load from template…" dropdown — extends WO create form (path TBD — verify, sits alongside uis-20c-create-edit-form.html spec)
New components: <WorkOrderTemplatesTable />, <TemplatePicker />, <TemplateBuilderForm />
API surface: GraphQL — new WorkOrderTemplate model, workOrderTemplates(options) + workOrderTemplate(id) queries, createWorkOrderTemplate / editWorkOrderTemplate / archiveWorkOrderTemplate mutations, loadFromTemplate(templateId) on WO create

Templates are an instance-wide library. A customer can opt to set a default template (so creating a WO for Cedar Ridge auto-loads their preferred template), but the library itself is shared. Permissions reuse instanceConfig.edit for management; any user with WO create permission can load a template.

2. UI Concept

Two surfaces. Top: Settings → Work Order Templates tab — list of templates with quick stats. Bottom: the WO create flyout with the new "Load from template…" dropdown at the top.

3. Key decisions for Emma + Corey to discuss

D1 Are templates instance-wide or per-customer-default?
Recommended: Instance-wide library + optional per-customer default. WorkOrderTemplate is global; Customer.defaultWorkOrderTemplateId is a nullable FK that auto-loads when creating a WO for that customer (overridable). Mirrors uis-20a-job-type-config.
D2 Do templates carry their forms list?
Recommended: Yes. Default forms attach via the existing job-form assignment plumbing (per master plan #28). Pairs with WOX-06 (assigned-only visibility) so each form has a sensible default scope at template-creation time.
D3 What permission gates template management?
Recommended: Reuse instanceConfig.edit for create/edit/archive. Any user with workOrder.create can load a template. No new permission flag needed for V1 (matches V0 dispatch toggle posture).
D4 Should "Save as template" exist on the WO detail page?
Recommended: Yes — but post-V1 (master plan item #34, deferred). 1.33 ships templates that admins build manually. The reverse flow ("save this WO as a template") is item #34, ~2d post-V1.
D5 Do templates pre-fill labor/equipment hours?
Recommended: No for V1 — defer to item #36 (blocked on dispatch flow per Emma: "timesheets need dates"). Templates pre-fill placeholder labor lines (see WOX-05) but never pre-fill timesheet entries.
