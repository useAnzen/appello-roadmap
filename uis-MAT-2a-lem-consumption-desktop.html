LEM Material Consumption — Desktop

Promotes the existing WorkOrderMaterialItem into a top-level, approvable pricing record — the material peer of Timesheet and Equipment Time — completing the LEM trifecta. Desktop entry UI, combined daily LEM report, and P&L integration.

Parent: Release 1.33 Slice: MAT-2a Est: 5–7 days
Reconciled against the live backend

The original draft proposed a net-new MaterialConsumptionEntry model. The live backend already ships WorkOrderMaterialItem (migration 20260409200000_work_order_line_item_tables) — the material sibling of WorkOrderLaborItem / WorkOrderEquipmentItem, wired into the combined upsertWorkOrderLineItems mutation, and already carrying materialAttributePriceId (the MAT-0 source row). It is dual-mode out of the box: free-text or a catalog Material + axes resolving to a specific MAP. This slice promotes that row into a structured, approvable pricing record — the material analogue of EquipmentTimeEntry — rather than building a parallel model. No MaterialConsumptionEntry.

1 · Business Case & Customer Evidence ▼

The “M” in LEM. Labour tracking is a structured, approvable record (Timesheets); Equipment tracking is too (Equipment Time, UIS-15H) — but Material consumption (“we used 24 batts of R-30 today”) only exists as a bare line-item row, with no status, cost codes, or billable value. Customers fall back to custom forms, losing structured data, cost-code allocation, and any connection to job financials. This slice gives Material the same structured-pricing tier as its LEM siblings.

Customer Evidence

“A full material management system will provide a more robust solution than our current form-based approach.” — St. Clair Mechanical (Demo, Feb 2026)
“We need a T&M daily report with separate sections for labor, materials, and equipment.” — AB Insulation (Form-Building Session, Nov 2024)

2 · Scope ▼

In Scope

  • IN Promote WorkOrderMaterialItem to a structured pricing record: add workDate, status (ApprovalStatus) + submit/approve audit trail, and free-text unitPropertyValueId
  • IN New WorkOrderMaterialItemCostCode join — per-line, account-item-typed cost coding (mirrors EquipmentTimeEntryCostCode)
  • IN Extend the existing upsertWorkOrderLineItems material path (carry workDate / status / cost-code splits); add an approveWorkOrderMaterialItems mutation
  • IN Desktop entry UI on Job / Work Order detail (catalog XOR free-text, quantity, cost-code split, status)
  • IN LEM combined daily report tab, keyed on (job, workDate), sourced from the three structured-tier records
  • IN LEMReportView SQL view aggregating the three LEM dimensions by job & work date
  • IN PDF export of LEM report
  • IN Material consumption cost (stored snapshot) + billable value in the Job Financial Summary

Out of Scope

  • OUT Mobile entry (deferred to MAT-2b)
  • OUT Inventory deduction on consumption
  • OUT Offline support
  • OUT Bulk import of consumption data
  • OUT Folding the bare unstructured WorkOrderLaborItem / WorkOrderEquipmentItem quick rows into the LEM report — the report draws labour & equipment from the structured-tier records (Timesheet, Equipment Time)

4 · Data Model ▼

Locked decisions:
  • Stored cost snapshot kept — unitPrice / costPrice / total are captured at entry (the price as consumed, not a drifting catalog price), matching the labour & equipment pricing records. total recalculates on create/edit.
  • Dual-mode, catalog XOR free-text — either materialId (+ axes → materialAttributePriceId, the MAT-0 source row) or a free-text description.
  • UoM is derived, not duplicated — catalog rows resolve unit of measure from Material.UnitPropertyValue; the new unitPropertyValueId is set only on free-text rows where there is no Material to read from.
  • Cost coding is per-line and account-item-typed — a join table referencing material-typed CostCodes, so a material code is never confused with a labour code.

model WorkOrderMaterialItem {

WorkOrderMaterialItemCostCode (new)

Per-line cost-code split, mirroring EquipmentTimeEntryCostCode / TimeSheetDetailRecordCostCode. EquipmentTimeEntryCostCode splits by approvedDuration; the material analogue splits by quantity.

model WorkOrderMaterialItemCostCode {
  id         String   @id @db.VarChar(21)
  isDeleted  Boolean  @default(false)
  isArchived Boolean  @default(false)
  createdAt  DateTime @default(now())
  updatedAt  DateTime @default(now()) @updatedAt

  workOrderMaterialItemId String                @db.VarChar(21)
  WorkOrderMaterialItem   WorkOrderMaterialItem @relation(fields: [workOrderMaterialItemId], references: [id], onDelete: Cascade, onUpdate: Cascade)

  costCodeId String   @db.VarChar(21)
  CostCode   CostCode @relation(fields: [costCodeId], references: [id], onDelete: Restrict, onUpdate: Cascade)

  quantity Decimal? @db.Decimal(10, 2)

  @@index([workOrderMaterialItemId, costCodeId, isDeleted])
}

LEMReportView (SQL View)

Built from the three structured-tier records — not the bare unstructured WorkOrderLaborItem / WorkOrderEquipmentItem quick rows (which carry no cost codes, billable rates, or status). Keyed on workDate. 
-- apps/api/prisma/views/LEMReportView.sql
-- Daily LEM aggregation keyed on (jobId, workDate)
SELECT
  jobId,
  workDate,
  SUM(laborHours)            AS laborHours,
  SUM(laborCost)             AS laborCost,
  SUM(laborBillable)         AS laborBillable,
  SUM(equipmentHours)        AS equipmentHours,
  SUM(equipmentCost)         AS equipmentCost,
  SUM(equipmentBillable)     AS equipmentBillable,
  SUM(materialQty)           AS materialQty,
  SUM(materialCost)          AS materialCost,
  SUM(materialBillableValue) AS materialBillableValue,
  SUM(laborCost) + SUM(equipmentCost) + SUM(materialCost)             AS dailyCostTotal,
  SUM(laborBillable) + SUM(equipmentBillable) + SUM(materialBillableValue) AS dailyBillableTotal
FROM (
  -- Labour CTE    — TimeSheet / TimeSheetDetailRecord (Approved); billable via TradeLevelRate (LEM-1)
  -- Equipment CTE — EquipmentTimeEntry (Approved); billable via equipment rates (LEM-2)
  -- Material CTE  — WorkOrderMaterialItem (Approved); cost = stored snapshot, billable via resolveMaterialSellPrice (LEM-3)
) combined
GROUP BY jobId, workDate
ORDER BY workDate DESC;

7 · Acceptance Criteria ▼

  • A user with the new WorkOrderMaterialItem:create permission can log a material consumption row from the Job / Work Order detail page (separate from MaterialOrder permissions; this same permission also governs material lines on Work Orders)
  • The entry form requires workDate and quantity > 0; submission is blocked if either is missing
  • Either a catalog Material (resolving to a materialAttributePriceId) or a free-text description must be provided — both empty is rejected
  • Catalog rows derive unit of measure from Material.UnitPropertyValue and leave unitPropertyValueId null; free-text rows require a unitPropertyValueId chosen from the unit PropertyValue list
  • On create/edit, total recalculates from the stored quantity × unitPrice snapshot
  • New rows default to NotSubmitted; the status workflow follows the ApprovalStatus enum (NotSubmitted / InReview / Approved / Rejected) at parity with Equipment Time
  • Approving stamps approvedByUserId + approvedOnApplicationId; submitting stamps the submit audit fields
  • The bulk approveWorkOrderMaterialItems mutation transitions multiple rows to Approved in one call
  • A single consumption row can be split across multiple material-typed cost codes via WorkOrderMaterialItemCostCode; labour-typed codes are not selectable
  • The LEM Report tab displays a combined daily view keyed on (job, workDate), sourced from the structured-tier records — Timesheet (labour), Equipment Time (equipment), and WorkOrderMaterialItem (material) — with both cost and billable values
  • The bare unstructured WorkOrderLaborItem / WorkOrderEquipmentItem quick rows are not double-counted into the LEM Report
  • The LEM Report shows materialBillableValue (LEM-3 cascade) alongside materialCost (stored snapshot), matching the cost vs. billable pattern used for labour and equipment
  • The LEM Report supports date-range filtering and shows a summary totals row
  • The LEM Report can be exported as a formatted PDF with job header, daily breakdown, and signature line
  • Material consumption (stored cost snapshot + billable value) appears in the Job Financial Summary
  • Cost-code allocation on consumption rows flows through to cost-code-level budget reports
