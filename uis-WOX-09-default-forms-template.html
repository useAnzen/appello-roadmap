Default Forms per WO Template

A WO Template (WOX-02) carries a list of forms that auto-attach when a WO is created from it. "HVAC Quarterly Service" auto-attaches HIRA + Gas Pressure Check + Customer Signoff. No more dispatcher attaching the same 3 forms 50 times a week.

Status: Concept Effort: ~1d (re-uses job-form plumbing) Extends: WOX-02 · F01 Master ref: #28

1. Where this lives in the app

Page / route: WO Template edit page (introduced in WOX-02) at /property-settings/work-orders/templates/[id] (path TBD — to be created in WOX-02)
Components touched: WorkOrderTemplateEditForm.tsx (TBD — WOX-02 component) — gains a new "Default forms" section. Reuses the form picker pattern from apps/frontend/src/components/Forms/JobAddEditForm/JobDataModelForm.tsx (verified — existing job-form assignment plumbing)
New components: WorkOrderTemplateDefaultFormsPicker.tsx (path TBD — colocated with WOX-02 template form components)
Backend / data model: WorkOrderTemplate.defaultFormIds: string[] (or a join table WorkOrderTemplateForm with per-form scope mode)
API surface: GraphQL — extends workOrderTemplate query result + editWorkOrderTemplate mutation. Form auto-attach happens inside createWorkOrderFromTemplate(templateId, ...) mutation.

This UIS sits squarely on top of WOX-02 (WO Templates) and re-uses the existing job-form assignment plumbing — there is no new "form attachment" mechanism to invent. The template just stores a default list, and the create-from-template mutation walks that list and attaches each one to the new WO. Per-form scope mode (ASSIGNED_USER_ONLY vs ALL_CREW) follows WOX-06's pattern.

3. Key decisions for Emma + Corey to discuss

D1 Forms attached per visit/day or per WO?
Recommended: Per WO. Use WOX-06 scope-mode controls (ASSIGNED_USER_ONLY vs ALL_CREW) for per-user visibility within the WO. Per-day attachment opens a new dimension we don't need for V1 and creates ambiguity on multi-day WOs (which day does the customer signoff belong to?).
D2 Can dispatcher remove a default form on create?
Recommended: Yes. Templates set the default, not the contract. Dispatcher gets a small chip-with-X to remove a form pre-creation. Removed forms log to the WO audit trail with a "removed by <user>" note.
D3 Changing template forms — apply to existing in-flight WOs?
Recommended: No — template change applies to new WOs only, with an optional admin-only "Apply to in-flight" button. Silently mutating in-flight WOs would break the audit chain ("when did this form appear and why?"). The opt-in button surfaces the consequence.
D4 Form scope mode (WOX-06 ASSIGNED_USER_ONLY vs ALL_CREW) — set on template?
Recommended: Yes, per form on template. The HIRA is "assigned only" 99% of the time; the Customer Signoff is too. The Gas Pressure Check is "all crew" because two-tech jobs check both ends. Setting it on the template eliminates per-WO toggling.
D5 Should removed default forms be re-addable post-create?
Recommended: Yes via the standard "Add form" picker — and the picker should pre-pin the template's defaults at the top with a small "default — was removed" hint, so a tech can easily restore one.
