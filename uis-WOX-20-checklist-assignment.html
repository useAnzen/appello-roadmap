Checklist User/Role Assignment

Extends the V1 checklist (WOX-03) so each item can be assigned to a specific user OR a role (e.g. "Foreman", "Apprentice"). Mobile filters the checklist to "items I'm responsible for" first, then "items the crew is responsible for". Drives accountability.

Status: Concept · Deferred Effort: ~3d · V2 Extends: WOX-03 · WO-3 Master ref: #37

1. Where this lives in the app

Page / route: WO desktop detail Checklist tab + mobile WO detail Checklist tab (paths follow WOX-03 · path TBD until V1 lands)
Components touched: <ChecklistItem />, <ChecklistEditor /> (from WOX-03), mobile WO list view
New components: <AssigneePicker /> (user-or-role chip), <ChecklistResponsibilityFilter /> (mobile)
API surface: Prisma migration adds assignedUserId String? + assignedRoleId String? to WorkOrderChecklistItem; existing updateWorkOrderChecklistItem mutation gains both fields

Reuses the V1 WorkOrderChecklistItem model from WOX-03. We add two nullable foreign keys — assignedUserId (specific person) and assignedRoleId (broader role bucket). Either, neither (= "anyone with access"), or both can be set; if both, user wins for accountability while role is preserved for templated reuse.

Desktop adds an inline assignee chip on each row. Mobile flips the experience entirely — instead of one long list, the checklist groups by responsibility: Mine (specifically me OR my role), Crew (other named users / roles on this WO), All (unassigned + everything). This is the actual accountability lever Emma flagged.

2. UI Concept

Desktop checklist editor with assignee chips. Mobile view filtered to "Mine (3) / Crew (2) / All (8)" with grouped sections.

3. Key decisions for Emma + Corey to discuss

D1 Assignment scope — user, role, or both?
Recommended: Either. Set assignedUserId for accountability, assignedRoleId for templates, both for "this person in this role". User wins for "Mine" filtering when both are set; role is kept for audit + template reuse.
D2 Default assignment when WO created from template?
Recommended: Copy role assignments from the template (they generalize); leave user assignments to the dispatcher who knows who's actually working that day. Template "Foreman" → WO "Foreman" → dispatcher resolves to Mike Lemay on Tuesday.
D3 Audit trail on reassignment?
Recommended: Yes — full history row per change (who, when, from→to). Same audit pattern as WO status transitions. Cheap to add and Emma flagged accountability as the whole point of the feature.
D4 Notify assignees?
Recommended: Push notification on mobile when an item is newly assigned to me, plus a daily 7:00 AM email digest on desktop summarizing the day's items. No notification on bulk role assignment (templates) — would spam the whole crew.
D5 Unassigned items — who can complete them?
Recommended: Anyone with WO access (V1 default — same as WOX-03). Show them in the "All" tab on mobile and an "Unassigned" pill on desktop. This is the back-compat path for existing WOX-03 data.
