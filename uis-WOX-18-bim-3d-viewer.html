BIM / Revit / IFC 3D Viewer

Mechanical and HVAC contractors need to navigate 3D Revit / IFC models on-site to find a specific zone, a piece of equipment, a duct run. Embed a lightweight 3D viewer (Autodesk Forge) so a user opens a model uploaded to a Project or Job and orbits, sections, and measures it inside Appello — no download / external app / re-upload loop. Killer feature: tap a duct or unit in the model → create a WO with that element as the subject (ties to WOX-04 equipment-as-subject).

Status: Concept · 1.34+ candidate Effort: ~10-15d · external SDK Extends: WOX-04 · UIS-15A Master ref: #32 — UIS-BIM

1. Where this lives in the app

Pages / routes: new Models tab on Project detail (apps/frontend/src/pages/projects/[id]/index.tsx) · same tab on Job detail (apps/frontend/src/pages/jobs/[id]/index.tsx)
New backend model: BimModel with parentEntityType · parentEntityId · fileUrl · viewerType (FORGE · SPECKLE · IFC_JS) · fileName · fileSize · uploadedByUserId · version
New components: components/BimViewer/BimViewerCanvas.tsx (Forge SDK wrapper) · BimModelList.tsx · PinToWorkOrderDialog.tsx
API surface: GraphQL — bimModels(options) · uploadBimModel (signed URL pattern) · createWorkOrderFromBimElement(modelId, elementId, ...)
Storage: Appello CDN for paid tiers · external link for free tier (D2 below)

Forge is a hosted SDK — uploads are translated server-side by Autodesk, then rendered via their JavaScript viewer. The "pin → WO" feature uses Forge's getProperties API to extract the element's name + family, pre-fills a WO create flyout with that element pre-selected as the subject equipment.

2. UI Concept

Project detail "Models" tab — list of uploaded models on the left, full-width 3D canvas on the right with section-cut, layer toggles, and a Pin → New WO tool that lets a user click any duct, RTU, or pipe in the model to spawn a WO with that element as the subject.

3. Key decisions for Emma + Corey to discuss

D1 Viewer engine — Autodesk Forge, Speckle, IFC.js, or xeokit?
Recommended: Autodesk Forge. Best Revit support (it's Autodesk's own format), full IFC support, mature SDK, hosted translation. Speckle is the fallback for non-AEC files. IFC.js / xeokit are open-source paths worth a 1-day spike but production-readiness is the risk.
D2 Storage — Appello CDN or external link?
Recommended: Tiered. Paid customers get Appello-hosted (S3 + CloudFront), free / trial get external link only (paste a OneDrive / SharePoint URL similar to WOX-15). Forge translation is metered — hosting our own bytes lets us amortize.
D3 Max model size?
Recommended: 500 MB initial cap. Raise based on real usage signal — 99% of mechanical models clear at < 250 MB. The cap is a pragmatic guardrail against accidentally uploading a 4 GB federated model that bricks the viewer.
D4 Mobile experience?
Recommended: Read-only orbit on phones (Forge mobile viewer handles this fine). Full nav + section + pin on tablets — that's where James Turpin's Detroit field-visit need actually lives. Phone viewport doesn't have the real-estate for the toolset.
D5 Link a model element → WO ("pin to WO")?
Recommended: Yes — this is the major delighter. Ties WOX-18 directly to WOX-04 (equipment-as-subject). Tap RTU-3 in the 3D model → spawn WO pre-filled with subjectEquipmentId = EQ-RTU-3. No competitor (Procore, CompanyCam, Clearstory) closes this loop.
