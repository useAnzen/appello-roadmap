SharePoint Phase 1 — Paste-Link MVP

Customers like Mak Surveying and Owens Insulation live in SharePoint. Phase 1 is the simplest possible integration: an External documents widget on Job / Project / WO detail pages where users paste a SharePoint (or any) link, label it, and click to open in a new tab. No iframe yet — that's Phase 2 (WOX-17). Solves the "where's the latest scope doc?" problem in V1 with ~2 days of work.

Status: Concept · V1 candidate Effort: ~2d Extends: uis-20d detail page Master ref: #30 — UIS-DOC-1

1. Where this lives in the app

Pages / routes: apps/frontend/src/pages/jobs/[id]/index.tsx · apps/frontend/src/pages/projects/[id]/index.tsx · WO detail page (path TBD — built under WO-4)
New components: components/ExternalDocuments/ExternalDocumentsWidget.tsx · AddExternalDocumentForm.tsx · ExternalDocumentRow.tsx
New backend model: ExternalDocument with parentEntityType (JOB · PROJECT · WORK_ORDER) · parentEntityId · url · label · addedByUserId · sourceDomain (cached) · createdAt
API surface: GraphQL — externalDocuments(options) list query · addExternalDocument · removeExternalDocument · updateExternalDocument

Same widget rendered on all three entity types via the polymorphic parentEntity pattern. Mobile mirrors the desktop UI on the WO mobile detail page. The model is intentionally provider-agnostic — Phase 2 (WOX-17) extends this same model with a provider enum and an iframe viewer.

3. Key decisions for Emma + Corey to discuss

D1 Validate the URL — format only or fetch the URL server-side?
Recommended: Format check only (RFC-3986 valid URL). Never server-fetch the URL. Server-fetching pasted user URLs is a SSRF vector — the V1 rule is "we store strings, we don't dereference them".
D2 Auto-detect favicon / preview?
Recommended: Client-side fetch with fallback to a hardcoded source-domain badge (SP / PC / DB / GD / OneDrive / "?"). Same SSRF caveat — origin must be the user's browser, not our server. Cheap, small win for recognisability.
D3 Permission model — who can add / remove?
Recommended: Anyone with edit on the parent entity (job · project · WO). Same permission gate as adding a comment. Granular doc-level perms are over-engineering for V1.
D4 Audit / lock for compliance customers?
Recommended: Track add / remove in the existing audit log. No lock in V1 — too easy to imagine and too painful to ship correctly. Promote to a flag if a customer explicitly asks.
D5 Mobile mirror?
Recommended: Yes — same widget on mobile WO detail. Tap a row → opens in the device's default browser. Pasting a URL on mobile is the awkward part; long-press paste-from-clipboard is enough.
