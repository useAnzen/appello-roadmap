WO Pricing Visibility — Financial Permission Gate

WO line items currently show cost+billable rates to every assignee. Tie all pricing visibility on WO detail (desktop + mobile) to the existing job.financialView permission. Techs without that permission see line items without dollar columns. Per master plan: ship V1; defer dedicated workOrder.viewPricing permission to WOX-24 post-V1.

Status: Concept · gate-only Effort: ~0.5d Extends: uis-20d · WO-3/WO-4 Master ref: #17

1. Where this lives in the app

Desktop page: WO detail page Labor / Materials / Equipment tabs (path TBD — to be created in WO-4 / uis-20d). Pricing block columns and totals get wrapped in a permission check.
Mobile page: WO detail (TBD — WO-8). Same gate, same hidden columns / totals.
Permission helper: apps/frontend/src/lib/permissionHelpers.ts (verified — exports hasPermissions) used in existing pages like apps/frontend/src/pages/jobs/[id]/index.tsx (verified) for the job.financialView check
New components: FinancialGate.tsx wrapper (path TBD — could live in apps/frontend/src/components/_PermissionGates/) — thin wrapper around hasPermissions that renders children or fallback
API surface: No GraphQL changes required — re-uses existing job.financialView permission already present on the user's role. PDF/print export gates inside apps/frontend/src/components/PdfRenderer/* (path TBD — verify with existing print pipeline)

This is the lightest change in the WOX batch — pure wrapping of existing UI in a permission-aware container. No new permission machinery, no new schema, no new resolver. The dedicated workOrder.viewPricing permission is intentionally deferred to WOX-24 post-V1; for 1.33 we lean on job.financialView because it already maps to the right human roles (project managers, accounting, owners — not field techs).

3. Key decisions for Emma + Corey to discuss

D1 Hide entire columns or show "—"?
Recommended: Hide entire columns — cleaner. The "—" approach makes the table feel broken; the absence of a column reads as intentional. The lock icon in the totals area is enough signal that pricing exists but is gated.
D2 Totals at the bottom — same gate?
Recommended: Yes. Showing aggregates while hiding line items is "security theatre" — a tech can compute approximate $/hr from one visible total. Hide the cost/billable/margin total rows but keep hours total visible (techs need to see crew hours to do their job).
D3 PDF / print export — gate per recipient?
Recommended: Gate to creator's permission at print time, with a watermark "Pricing visible only to financial roles." Per-recipient gating is impossible for printed PDFs. The watermark is a paper-trail mitigator: if a tech ends up holding a printed copy with pricing, the watermark documents the source.
D4 How to message users who lose access mid-flow?
Recommended: Gentle inline banner ("Pricing hidden — your role doesn't include Job Financial View") with a "Why?" link to a 2-sentence help article. Avoid a modal/toast — tech opens WO 50× a day; a modal becomes click-through fatigue.
D5 Future dedicated workOrder.viewPricing permission?
Recommended: File as WOX-24 post-V1. Default the new permission to ON for anyone who already has job.financialView (back-compat — no surprises on rollout). Then admins can selectively turn it OFF for users who should see job financials but not WO pricing (rare but real for some senior tech roles).

4. Roadmap context

Per the master plan's resolved conflict point: tie WO pricing to job.financialView for V1 (Emma's "defer entirely" position softened to "tie to existing permission"; Corey's "new junior/senior workflows" deferred to post-V1). This is the cheapest, lowest-risk way to ship pricing safety in 1.33 without inventing new permission UX.
