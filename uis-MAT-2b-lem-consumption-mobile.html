LEM Material Consumption — Mobile

Mobile material-consumption logging for field workers, built by reusing the existing MaterialItemEditor (the WO create-flow material picker) over the MAT-2a backend. No new backend, no new picker.

Parent: Release 1.33 Slice: MAT-2b Est: 3–4 days
Reconciled against the live backend

The original draft targeted a net-new MaterialConsumptionEntry / createMaterialConsumptionEntry and leaned on offline sync. Reality: consumption rows are WorkOrderMaterialItem (MAT-2a), written through the existing upsertWorkOrderLineItems mutation, and the catalog + variant + pricing UI already exists as MaterialItemEditor (packages/ui), wired on mobile via MobileWOMaterialEditor — the same component the Work Order create flow uses. So MAT-2b is a thin wrapper: reuse that editor, add a work-date picker, a cost-code split, and submit/status wiring, plus a history list and a job-view tab. No new backend, no new picker. Offline sync is dropped (siblings don’t queue offline); status uses ApprovalStatus, not sync badges.

1 · Business Case & Customer Evidence ▼

Field workers consume materials daily but have no native way to log it from their phones. The current workaround is text messages, phone calls, or custom forms — none of which are linked to the material catalog or cost codes. This gap means consumption data arrives late, incomplete, and disconnected from the financial reporting chain. A mobile-first entry form closes the field-to-office loop, giving project managers real-time visibility into material burn and eliminating manual data re-entry.

2 · Scope ▼

In Scope

  • IN Mobile consumption form reusing MaterialItemEditor (catalog search + X/Y variant + live cost/sell pricing + free-text/manual mode), launched as a flyout from a date+job context
  • IN A work-date picker (the daily LEM anchor) wrapping the editor
  • IN A cost-code split section (reuse the equipment cost-code sub-row pattern, scoped to the material account category) writing WorkOrderMaterialItemCostCode
  • IN Submit/status wiring — submit sets ApprovalStatus = InReview (mirrors equipment-time mobile)
  • IN Consumption history list per job (status badges, swipe-to-edit)
  • IN A dedicated “Material” tab in SimplifiedJobTasks (gated on WorkOrderMaterialItem.create)

Out of Scope

  • OUT Any new backend — reuses WorkOrderMaterialItem + upsertWorkOrderLineItems from MAT-2a exclusively
  • OUT A new material picker — reuses MaterialItemEditor / MobileWOMaterialEditor
  • OUT Offline sync / local queueing (siblings don’t do it; not this slice)
  • OUT Approval as the primary mobile action (approval is desktop-primary; mobile approve only if the user holds WorkOrderMaterialItem.approve)
  • OUT Desktop entry UI (MAT-2a), inventory deduction (MAT-7)

4 · Data Model ▼

No new Prisma models. This slice writes WorkOrderMaterialItem (+ its WorkOrderMaterialItemCostCode children) from MAT-2a, via the existing upsertWorkOrderLineItems material branch. Most of the row is produced by MaterialItemEditor’s IMaterialRowData; MAT-2b supplies the wrapper fields (workDate, status, cost-code split).

Mobile Form → WorkOrderMaterialItem Field Mapping

Mobile Form FieldModel FieldSource
Material + variant (editor) materialId, materialAttributePriceId MaterialItemEditor → material + X/Y axis → resolved MAP source row
Free-text / manual row description MaterialItemEditor blank mode (no catalog match)
Quantity stepper quantity User input (Decimal, must be > 0)
Price (editor) unitPrice / costPrice / total Editor: catalog → resolveMaterialAttributePrice / resolveMaterialSellPrice; free-text → manual; total = qty × unitPrice
Unit (display only) unitPropertyValueId Catalog rows derive UoM from Material.UnitPropertyValue (null here); free-text rows set a unit PropertyValue

Work-date picker workDate Defaults to today; the daily LEM anchor
Submit action status + submittedByUserId Submit → InReview; submitter stamped from the authenticated user
(auto) jobId Current job context from route params

5 · API Surface ▼

No new API additions. The mobile app consumes the MAT-2a surface and the catalog/pricing queries MaterialItemEditor already uses. Status flows through the upsert input (submit sets InReview), so no dedicated submit mutation is required.

Consumed Mutation (write)

mutation UpsertWorkOrderLineItems($input: UpsertWorkOrderLineItemsInput!) {
  upsertWorkOrderLineItems(input: $input)   # materialItems[] branch
}
# each material item carries: workDate, materialId | description,
# materialAttributePriceId, quantity, unitPrice, unitPropertyValueId,
# status (InReview on submit), costCodes[]

Consumed Queries (read)

# history list for the job (date-range filterable — MAT-2a)
query WorkOrderMaterialItems($jobId: String!, $dateFrom: DateTime, $dateTo: DateTime) {
  workOrderMaterialItems(jobId: $jobId, dateFrom: $dateFrom, dateTo: $dateTo) {
    id workDate quantity unitPrice total status description
    Material { id name }
    MaterialAttributePrice { id }
    WorkOrderMaterialItemCostCodes { costCodeId quantity }
  }
}

# powering MaterialItemEditor (already used by MobileWOMaterialEditor):
#   resolveMaterialAttributePrice(...)   -> variant cost (MAP source row)
#   resolveMaterialSellPrice(...)        -> billable
#   material catalog search + X/Y axis value queries

MaterialItemEditor brings its own catalog-search + price-resolution queries (reused verbatim). The workOrderMaterialItems query powers the history list. upsertWorkOrderLineItems is called on submit; bulk approveWorkOrderMaterialItems is available only where the user holds the approve permission.

7 · Acceptance Criteria ▼

  • The form reuses MaterialItemEditor: catalog search, picking a material then its X/Y variant resolves the exact MAP price (cost + sell), and a free-text/manual row is supported
  • A workDate is required (defaults to today) and anchors the entry in the daily LEM report
  • Quantity validates > 0; the line cannot be submitted with zero or negative quantity
  • The cost-code picker shows only material-typed codes for the job; a line can split across several, writing WorkOrderMaterialItemCostCode rows
  • Estimated cost (qty × unit price) updates live as quantity changes (from MaterialItemEditor)
  • Submit writes via upsertWorkOrderLineItems and sets status = InReview, stamping the submitter; it does not auto-approve
  • Submitted entries appear in the per-job history list and in the desktop MAT-2a table / daily LEM report (same model)
  • History rows show ApprovalStatus badges (Not Submitted / In Review / Approved / Rejected) — not sync state
  • Swipe-to-edit opens the flyout pre-populated with the entry’s data
  • Permission: the “Material” tab + form require WorkOrderMaterialItem.create; mobile approve appears only with WorkOrderMaterialItem.approve
  • The “Material” tab appears in SimplifiedJobTasks and renders the history + entry flyout
