Multi-day WO Labor — Date Column

A multi-day WO (3-day boiler retrofit, week-long mechanical install) needs labor lines per-day, not just a lump sum. Add a date column to the labor table, default to WO start date for new lines, allow per-row date editing within (or warned-outside) the WO date range.

Status: Concept · polish Effort: ~1d (UI surface) Extends: LEM-1 · WO-2/WO-4 Master ref: #21

Per Emma's gap-cross-reference note, the underlying mechanic already groups properly — the labor model already carries a date for timesheet rollup. The only gap is the WO labor table doesn't surface that date as a column. This UIS is purely UI: add the column, make it editable inline within the WO range, add a group-by-date toggle, and update sub-totals.

3. Key decisions for Emma + Corey to discuss

D1 Default date for new lines?
Recommended: WO start date if today is before start; today if today is in range; end date if today is after. Three-rule heuristic matches the most common authoring intent. Avoids the trap of always-defaulting-to-today (which puts lines on yesterday for tomorrow's WO) and always-defaulting-to-start (which forces a date pick on every line for in-flight WOs).
D2 Date constraint to WO range or freeform?
Recommended: Warn outside WO range; allow with override. Hard-blocking creates support tickets when techs work pre-mobilization or do post-completion punch-list. The yellow warning chip ("OUTSIDE RANGE") is enough signal for office reconciliation.
D3 Group-by-date view?
Recommended: Yes, optional toggle. Defaults to flat list (most users want to see all lines at once). The grouped view is genuinely useful for week-long WOs where flat becomes a wall of rows. Toggle persists per-user as a preference (localStorage).
D4 When WO date range shrinks, what happens to lines outside the new range?
Recommended: Warn + require explicit move/delete. Modal on save: "3 labor lines fall outside the new date range. Move them to the closest valid date, leave them as warned, or remove?" Silent drop would be a payroll integrity disaster.
D5 Placeholder labor (WOX-05) date behavior?
Recommended: Placeholders don't have a date until resolved. Per the placeholder pattern's clean separation: pre-resolution placeholders are pure WO-side capacity, no date. On resolve via dispatch, the system writes the date alongside the user assignment.
