WO Pricing — Financial Permission Gate

Today every WO assignee sees cost + billable rates on the line items. This spec adds a new workOrder___viewPricing permission and gates WO pricing visibility (desktop + mobile + PDF) against it. Techs without the permission see line items without dollar columns — silent hide, per Appello convention (no banners, no watermarks). Path B build of WOX-11.

Estimate: 1-1.5 days Sequence: 1.33, after WO-3/WO-4 Requires: WO-1, WO-3, WO-4 Enables: Per-role pricing visibility config for admins

1. Business Case

WOs surface labor / equipment / material rates and totals to anyone with WO read access. For most service contractors this is fine — billable rate is a feature, not a secret. For some (junior techs, subcontractor crews on shared WOs, customers viewing exported PDFs) it isn't.

The existing financial permissions (job___salesSum, financial_summary___viewOwnFinancialDataOnly, report___viewAllJobCost) don't fit the WO-pricing-line-items use case — they gate aggregate sales / cost reporting, not per-line WO rates. Adding a new workOrder___viewPricing permission is a small lift (seed entry + permission check wiring) and gives admins a clean, role-scoped dial for the WO surface specifically.

The hide convention is silent: when a permission gates a UI element, the element is simply absent. No "pricing hidden" banner, no "permission required" stamp, no watermark on PDF exports. Users who lack the permission see the WO without dollar columns and infer the gating from role context the same way they do for every other gated surface in Appello.

2. Scope

Already Built

  • DONE <PermissionGate> wrapper component (existing) — used throughout the app for hide-on-no-permission patterns
  • DONE WO detail page scaffolding (WO-3, WO-4) — host for the gate
  • DONE Permission seed + role-grant infrastructure (existing) — used to introduce new permissions in prior releases

In Scope (WO-17)

  • IN New permission workOrder___viewPricing — seeded in the permissions table; available in the role editor
  • IN Migration that grants workOrder___viewPricing to every existing role that currently has WO edit/read access — preserves existing behavior on rollout (no role suddenly loses pricing visibility)
  • IN Wrap WO line item pricing columns (cost, billable, margin, total) in <PermissionGate permission="workOrder___viewPricing"> on desktop WO detail (Labor / Materials / Equipment tabs)
  • IN Same gate on mobile WO detail (the rendered list / detail surfaces)
  • IN Hide cost / billable / margin / total aggregate rows at the bottom of each table — keep the hours total visible (techs need it for crew planning)
  • IN WO PDF / print export — gate at print time using the creator's permission. When the creator has workOrder___viewPricing, pricing renders; otherwise the same columns / totals are stripped from the export. No watermark, no "pricing redacted" stamp — silent hide matches the in-app convention.

Out of Scope

  • OUT Banners / stamps / watermarks on gated surfaces — the Appello convention is silent hide; no informational chrome about why something is hidden
  • OUT Per-recipient PDF gating — impossible for printed copies; gating at the creator's permission is the V1 line
  • OUT Showing "—" or "$ ---" placeholders in pricing columns — hide entire columns instead (placeholders read as broken UI)
  • OUT Mid-flow modal / toast when permission is removed live — page reload picks up the new state
  • OUT Gating on the WO list page columns — list page does not currently expose pricing per row; if it gains a Total column it inherits this gate at that time

3. UI Concepts

The gated view of each surface is identical to the un-gated view minus the pricing columns / totals. No banner, no stamp, no informational chrome. Mockups in Corey's WOX-11 show the column layouts; adopt the column-hiding visuals but skip the banner / watermark elements.

Interfaces affected

  • Desktop WO Detail · Labor tab — gates cost/billable/margin/total columns + bottom totals row (keeps hours total visible)
  • Desktop WO Detail · Materials tab — gates unit price / total columns + totals row
  • Desktop WO Detail · Equipment tab — gates unit rate / total columns + totals row
  • Desktop WO Detail header — pricing summary chips ($ total) hidden when gated
  • Mobile WO Detail — same gating in mobile list views
  • WO PDF / print template — pricing rendered conditionally based on creator's permission; when stripped, the columns simply do not render
Hide convention: the platform's existing pattern is "if you don't have the permission, the UI element isn't there." We don't tell users why — they learn through role context. Same for PDF exports: when stripped, pricing columns are simply absent from the rendered document.

4. Data Model

One new permission row in the existing permissions table — no new models, no new columns on existing models.

4.1 Permission seed

INSERT IGNORE INTO `Permission` (`id`, `key`, `label`, `category`)
VALUES (
    'PSEED_workOrder_viewPricing',
    'workOrder___viewPricing',
    'Work Order — View pricing',
    'workOrder'
);

4.2 Migration: grant to existing roles

-- Preserve existing behavior: any role that currently has WO read or
-- edit access automatically receives the new view-pricing permission.
-- Admins can selectively turn it OFF for tech roles after rollout.
INSERT IGNORE INTO `RolePermission` (`roleId`, `permissionId`)
SELECT DISTINCT rp.roleId, 'PSEED_workOrder_viewPricing'
FROM `RolePermission` rp
INNER JOIN `Permission` p ON p.id = rp.permissionId
WHERE p.`key` IN ('workOrder___view', 'workOrder___edit');
-- (exact source permission keys per the existing WO permissions seeded
-- in WO-1 / WO-3; verify against current schema before running)
Why grant on rollout: introducing a new permission with no automatic grant would silently strip pricing from every existing role on deploy day — surprising and disruptive. Grant-to-existing preserves the current "everyone with WO access sees pricing" behavior; admins then turn it OFF deliberately for the roles that shouldn't (tech / subcontractor crews).

5. API Surface

No new GraphQL types, queries, or mutations. Pricing fields on existing WO types remain — the GraphQL layer doesn't strip pricing data, the UI does. Resolvers continue to return cost / rate / total for users with Job___financialView; for users without, the UI hides the columns rather than the resolver returning null.

Why client-side gating is OK here: the existing Job-side pricing already does this; backend stripping would require a parallel set of resolvers and would break shared components. Permission consistency comes from the existing PermissionGate wrapper hitting the same auth context.

7. Acceptance Criteria

  1. A new permission workOrder___viewPricing exists in the permissions table after migration; it appears in the role editor under the "Work Order" category.
  2. The migration grants workOrder___viewPricing to every role that currently has WO read or edit access — existing users see no behavior change on deploy day.
  3. A user with workOrder___viewPricing sees all pricing columns and totals on every WO detail surface (desktop + mobile).
  4. A user without workOrder___viewPricing sees WO line item rows without cost / billable / margin / total columns; the columns are hidden, not blanked.
  5. The hours / qty / duration columns remain visible on every tab regardless of pricing permission.
  6. Bottom-of-table aggregate rows (totals, margin) are hidden for gated users; only the hours / qty subtotal stays visible.
  7. No banner, stamp, or informational message tells gated users why pricing is hidden — silent hide per Appello convention.
  8. WO PDF export rendered by a creator with the permission includes pricing; rendered by a creator without it has the same columns / totals absent. No watermark.
  9. Permission revocation mid-session takes effect on the next page load — no special live-revocation UX needed.
  10. No new GraphQL queries, mutations, or types are introduced — only the permission seed + role-grant migration + UI gating wiring.
