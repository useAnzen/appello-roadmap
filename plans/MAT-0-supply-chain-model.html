MAT-0: Supply Chain Foundation — Per-Source Material Pricing (Implementation Plan)

Self-contained execution plan. Another agent should be able to pick this up cold, run the steps in order, and ship a PR. Every file path is relative to the monorepo root (apps/api, apps/frontend). Read the Pre-flight section first. Companion spec: uis-MAT-0-supply-chain-model.html (this file is the plan; that is the spec + decision log). Overview & Outcome

Give every material cost a source by extending the existing per-cell cost grid (MaterialAttributePrice, “MAP”) — no new top-level models. After this lands:

  • A MAP row can carry a (distributor + manufacturer) source (two nullable Company FKs), a sku, and procurement metadata (list/discount/effective dates/min qty/lead time/packaging/preferred/in-stock). A source-less row (both FKs null) is the “house” row — today’s behaviour, now also the variant’s catalogue record (own sku/barcode/weight).
  • The 0-axis price moves from Material.unitCost into an all-axes-null MAP house row (migrated), so single-SKU materials carry sources exactly like dimensional cells. unitCost becomes a transitional read-fallback.
  • MaterialPricingService.bestAvailableCost() — the hook LEM-3a reserved for MAT-0 — resolves the cheapest/preferred active source first, then the house row, then legacy unitCost. Signature unchanged, so every WO/IE/LEM sell-price consumer benefits automatically. The resolvedSellPrice TableFeed SQL mirror is updated to match.
  • A source’s distributor/manufacturer is gated against MAT-10’s MaterialCompany (role-aware): you can only price a company that is a declared supplier of that material.
  • Company detail gains Products / Products & Pricing tabs (by join-existence); Material detail shows per-source pricing with a “Best” marker.
Decisions — build against the spec leans, confirm before merge (spec §10). CTO is out; the spec is in review. None of these block building; all are cheap to flip.
  • Q-c (cost basis): preferred-wins-when-set, else lowest effectivePrice. Used in both the service and the SQL mirror below.
  • Q-d (SKU columns): ship sku + optional manufacturerSku + upc (cheap reference cols, Shopify-forward).
  • Q-e (delete of a referenced MaterialCompany): block while referenced by live source rows. Enforced in MAT-10’s MaterialCompany delete path (see Step 3.4) — coordinate the one-line guard there.
  • Q-b (generic vs brand Materials): CEO/users; schema works either way — no code impact.

MySQL nullable-unique caveat — the unique index alone is NOT enough. MySQL treats NULL as distinct in a unique index, so @@unique([…, distributorId, manufacturerId]) will not stop two house rows (both source FKs null) for one cell, nor two all-null rows for a 0-axis material. 2.2 Append the backfill (PART B) after the generated DDL

-- PART B: backfill 0-axis price (Material.unitCost) into an all-null MAP house row.
-- 0-axis = the material's group declares no pricing axis attribute.
INSERT INTO `MaterialAttributePrice`
    (`id`, `value`, `materialId`, `isArchived`, `isDeleted`, `createdAt`, `updatedAt`)
SELECT
    LEFT(MD5(UUID()), 21), m.unitCost, m.id, 0, 0, NOW(), NOW()
FROM `Material` m
JOIN `MaterialGroup` mg ON mg.id = m.materialGroupId
WHERE m.isDeleted = 0
  AND m.unitCost IS NOT NULL
  AND mg.pricingXMaterialAttributeId IS NULL
  AND mg.pricingYMaterialAttributeId IS NULL
  AND mg.pricingZMaterialAttributeId IS NULL
  AND NOT EXISTS (
      SELECT 1 FROM `MaterialAttributePrice` p
       WHERE p.materialId = m.id AND p.isDeleted = 0
         AND p.selectedXValueId IS NULL AND p.selectedYValueId IS NULL AND p.selectedZValueId IS NULL
         AND p.distributorId IS NULL AND p.manufacturerId IS NULL
  )
;

Then pnpm run prisma:deploy && pnpm run prisma:generate. The new source/SKU/procurement columns default to NULL/false on every existing row, so existing house rows (dimensional cells) become valid house rows with no further work.

Why not also backfill unitCost for dimensional materials? Their priced cells are already MAP rows; unitCost on a dimensional material is unused by bestAvailableCost today and stays a no-op fallback. Backfilling it would create a spurious all-null row that the cheapest-source/house resolution could pick up. Keep PART B 0-axis-only.

3.3 The source membership gate (role-aware) — validatePayload

public async validatePayload(input: Partial<IMaterialAttributePrice>): Promise<void> {
    await super.validatePayload?.(input);
    const materialId = input.materialId;

    // A source FK is only valid if the company is a declared MaterialCompany
    // of the MATCHING role for this material. Reject otherwise.
    if (input.manufacturerId) {
        const ok = await prisma.materialCompany.findFirst({
            where: { materialId, companyId: input.manufacturerId, role: "Manufacturer", isDeleted: false },
            select: { id: true }

        if (!ok) throw new BadRequestError(
            `Company ${input.manufacturerId} is not a Manufacturer of material ${materialId}. ` +
            `Link it via MaterialCompany first.`);

    if (input.distributorId) {
        const ok = await prisma.materialCompany.findFirst({
            where: { materialId, companyId: input.distributorId, role: "Distributor", isDeleted: false },
            select: { id: true }
        });

            `Company ${input.distributorId} is not a Distributor of material ${materialId}. ` +

3.5 Computed helpers: effectivePrice + cheapest/preferred

import { Decimal } from "@prisma/client/runtime/library";

// effectivePrice for one row (the cost basis used by the cascade).
// Resolves only the row's own linked Discount (the per-cell tier). A later
// slice generalises this into resolveBuyDiscount(distributor, material, cell)
// that ALSO walks the material/category/global blanket tiers — same seam.
public static effectivePrice(
    row: {
        value: Decimal | null;
        listPrice: Decimal | null;
        Discount: { type: string; value: Decimal } | null;
    }
): Decimal | null {
    const base = row.listPrice ?? row.value;
    if (base == null) return null;
    const d = row.Discount;
    if (!d) return base;
    return d.type === "Percent"
        ? base.mul(new Decimal(1).minus(d.value.div(100)))
        : Decimal.max(new Decimal(0), base.minus(d.value));   // FixedAmount
}

// Cheapest/preferred ACTIVE source cost across all of a material's cells (any-cell).
// Q-c: preferred wins when set, else lowest effectivePrice. Returns null if no active source.
public async cheapestSourceCostForMaterial(materialId: string): Promise<Decimal | null> {
    const now = new Date();
    const rows = await prisma.materialAttributePrice.findMany({
        where: {
            materialId, isDeleted: false, isArchived: false,
            OR: [{ distributorId: { not: null } }, { manufacturerId: { not: null } }],
            AND: [
                { OR: [{ effectiveFrom: null }, { effectiveFrom: { lte: now } }] },
                { OR: [{ effectiveTo: null }, { effectiveTo: { gte: now } }] }
            ]
        },
        select: {
            value: true, listPrice: true, isPreferred: true,
            Discount: { select: { type: true, value: true } }
        }
    });
    const priced = rows
        .map((r) => ({ ep: MaterialAttributePrice.effectivePrice(r), isPreferred: r.isPreferred }))
        .filter((r): r is { ep: Decimal; isPreferred: boolean } => r.ep != null);
    if (!priced.length) return null;
    const preferred = priced.filter((r) => r.isPreferred);
    const pool = preferred.length ? preferred : priced;
    return pool.reduce((min, r) => (r.ep.lt(min) ? r.ep : min), pool[0].ep);
}

(Material-level / any-cell, matching bestAvailableCost’s documented contract. A caller needing a specific cell’s cheapest source filters the same query by the cell’s selectedX/Y/ZValueId and passes the result as costPrice to resolveMaterialSellPrice.)

Replace the body of bestAvailableCost (30–64) — keep the exported signature (materialId: string) => Promise<Decimal | null> and rewrite the header comment (drop the DistributorPrice.effectivePrice/ManufacturerProduct wording — those models don’t exist; describe the collapsed model):

// Resolves a material's any-cell cost basis, cheapest-source-first:
//   1. cheapest/preferred ACTIVE source effectivePrice across the material's cells
//   2. the source-less "house" row (incl. the 0-axis all-axes-null row)
//   3. Material.unitCost — legacy transitional fallback only
// Signature must not change (LEM-3a contract). For a SPECIFIC (X,Y[,Z]) cell the
// caller resolves that cell's cheapest source and passes it as `costPrice` to
// resolveMaterialSellPrice — this is the any-cell / 0-axis fallback path.
export const bestAvailableCost = async (materialId: string): Promise<Decimal | null> => {
    // 1. cheapest/preferred active source
    const sourceCost = await new MaterialAttributePrice().cheapestSourceCostForMaterial(materialId);
    if (sourceCost != null) return sourceCost;

    // 2. latest source-less house row (axis cells AND the 0-axis all-null row)
    const house = await prisma.materialAttributePrice.findFirst({
        where: {
            materialId, isDeleted: false, isArchived: false,
            distributorId: null, manufacturerId: null
        },
        orderBy: { updatedAt: "desc" },
        select: { value: true }
    });
    if (house?.value != null) return house.value;

    // 3. legacy fallback
    const material = await prisma.material.findUnique({ where: { id: materialId }, select: { unitCost: true } });
    return material?.unitCost ?? null;
};
Why the hasAxis gate goes away. Today it routed 0-axis to unitCost and skipped MAP “so a stale row doesn’t shadow unitCost.” After Step 2 the 0-axis price is the all-null MAP house row, so reading the source-less house row is correct for both 0-axis and dimensional (any-cell) materials. unitCost only answers when no MAP row exists at all (pre-backfill stragglers / new 0-axis materials not yet priced).

Import the model at the top: import { MaterialAttributePrice } from "../models/MaterialAttributePrice";. resolveMaterialSellPrice (82–129) is unchanged — it already calls bestAvailableCost when no costPrice is supplied.

The current SQL uses m.unitCost as the cost basis in three places (the two markup branches + the ELSE). Replace that basis with a LATERAL-derived costBasis.cost that mirrors Q-c. Single-record version (apply the identical change to the batch selectBatchRecordSet, keying on m.id IN (${Prisma.join(recordIds)}) and selecting m.id AS recordId):

selectRecordSet: (record) => Prisma.sql`
    SELECT (
        CASE
            WHEN m.sellPriceOverride IS NOT NULL THEN m.sellPriceOverride
            WHEN m.markupPercentOverride IS NOT NULL
                THEN costBasis.cost * (1 + m.markupPercentOverride / 100)
            WHEN mg.defaultMarkupPercent IS NOT NULL
                THEN costBasis.cost * (1 + mg.defaultMarkupPercent / 100)
            ELSE costBasis.cost
        END
    ) AS value
    FROM Material m
    LEFT JOIN MaterialGroup mg ON mg.id = m.materialGroupId
    LEFT JOIN LATERAL (
        SELECT COALESCE(
            -- 1. cheapest/preferred ACTIVE source effectivePrice (row's own linked Discount)
            (SELECT (CASE
                        WHEN d.id IS NULL THEN map.value
                        WHEN d.type = 'Percent'
                            THEN COALESCE(map.listPrice, map.value) * (1 - d.value / 100)
                        ELSE GREATEST(COALESCE(map.listPrice, map.value) - d.value, 0)
                     END)
               FROM MaterialAttributePrice map
               LEFT JOIN Discount d
                      ON d.id = map.discountId AND d.isDeleted = 0 AND d.isArchived = 0
              WHERE map.materialId = m.id AND map.isDeleted = 0 AND map.isArchived = 0
                AND (map.distributorId IS NOT NULL OR map.manufacturerId IS NOT NULL)
                AND (map.effectiveFrom IS NULL OR map.effectiveFrom <= NOW())
                AND (map.effectiveTo   IS NULL OR map.effectiveTo   >= NOW())
              ORDER BY map.isPreferred DESC,
                       (CASE
                          WHEN d.id IS NULL THEN map.value
                          WHEN d.type = 'Percent'
                              THEN COALESCE(map.listPrice, map.value) * (1 - d.value / 100)
                          ELSE GREATEST(COALESCE(map.listPrice, map.value) - d.value, 0)
                        END) ASC
              LIMIT 1),
            -- 2. latest source-less house row (incl. the 0-axis all-null row)
            (SELECT h.value FROM MaterialAttributePrice h
              WHERE h.materialId = m.id AND h.isDeleted = 0 AND h.isArchived = 0
                AND h.distributorId IS NULL AND h.manufacturerId IS NULL
              ORDER BY h.updatedAt DESC LIMIT 1),
            -- 3. legacy fallback
            m.unitCost
        ) AS cost
    ) costBasis ON TRUE
    WHERE m.id = ${record.id}
`,
MySQL version: LATERAL needs MySQL 8.0.14+. If the target is older, inline the same COALESCE(…) expression directly into each of the three CASE branches (verbose but identical semantics) instead of the join. Verify against the engine the rest of prisma/views targets.

The ORDER BY isPreferred DESC, effectivePrice ASC LIMIT 1 exactly mirrors the service’s preferred-wins-then-lowest (Q-c) — no divergence between list view and resolver.

MAT-9 extends this: MAT-0’s subquery applies only the row’s own discountId.
