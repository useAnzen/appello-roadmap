Save WO as Template Action

User finishes a WO, realizes they'll do this same kind of work again. New action menu item "Save as template…" on WO detail — strips out customer-specific data, keeps line items, forms, checklist, trade levels. Inverts the WOX-02 flow (templates were created from scratch in V1).

Status: Concept · Deferred Effort: ~2d · V2 Extends: WOX-02 · WO-3 Master ref: #34

1. Where this lives in the app

Page / route: WO desktop detail header (path TBD — V1 builds it). Pattern follows apps/frontend/src/components/DetailsPage/JobDetailsPage/index.tsx
Components touched: WO detail action menu (path TBD), WO templates settings page (from WOX-02 — path TBD)
New components: <SaveAsTemplateDialog />, <TemplatePreviewPane /> (path TBD)
API surface: GraphQL — createWorkOrderTemplateFromWorkOrder(workOrderId, name, includeForms, includeChecklist, includeLineItems, includeTradeLevels) mutation

The V1 WOX-02 flow only supports creating templates from scratch. This adds the inverse — start from a real WO that's already been built and capture what worked. Same destination model (WorkOrderTemplate), so existing template-consumer surfaces work unchanged.

The mutation strips customer-specific identifiers (customer, site, WO number, dates, technician assignments, photos, signatures) by default and copies the structural pieces (line items, forms, checklist, trade levels, default labor estimates) based on user-selected checkboxes. The result is a usable template the dispatcher can reuse next time.

2. UI Concept

WO detail action menu shows "Save as template…" — clicking opens a dialog with name + include checkboxes + a preview of what gets reset. Save lands a success toast plus a "View in Settings" deep link.

3. Key decisions for Emma + Corey to discuss

D1 What gets stripped vs preserved?
Recommended: Always strip customer / site / dates / users / photos / signatures (PII + tenant-specific). Everything structural (line items, forms, checklist, trade levels, notes) is opt-in via checkboxes. Default all structural boxes ON — that's the value.
D2 Template ownership / scope?
Recommended: Instance-wide by default (matches WOX-02 V1 behavior). Add a "Customer-specific" toggle that scopes the template to the source customer if checked — useful for "Cedar Ridge always wants this exact set of forms" patterns.
D3 Placeholder labor lines (WOX-05) — preserve qty + trade level?
Recommended: Yes — preserve the placeholder qty + trade level on each labor line; clear the resolved userId. That's exactly the value of saving from a real WO ("we always need 1 Foreman + 1 Journeyman for ~2.5h on this job type").
D4 Permission to save?
Recommended: Same permission as managing WO templates (see WOX-02). If you can edit templates, you can save one from a WO. Keeps the permission model simple and matches the mental model.
D5 Batch convert from existing WOs?
Recommended: Defer — V2 is single-WO-at-a-time. Batch tooling lives in a future admin utility (post-1.34) once we see if customers actually want it. YAGNI for now.
