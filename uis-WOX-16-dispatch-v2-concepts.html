Dispatch Board V2 — 3 Industry Concepts

V0 (WOX-01) is just a calendar toggle. V2 is the real dispatch board. Three side-by-side concepts inspired by category leaders: (A) ServiceTitan-style "Tech Day Grid", (B) Jobber-style "Day-Strip Timeline", (C) Housecall Pro-inspired "Map-First Dispatch". One mock per concept, one comparison table, one recommendation — pick before 1.34 planning.

Status: Concept · Selection needed Effort: A ~12d · B ~8-10d · C ~14-16d Extends: WOX-01 V0 toggle Master ref: #26 — WO-9b Dispatch V2

1. Where this lives in the app

Page / route: new /dispatch top-level page (replaces the WOX-01 V0 toggle once shipped) · entry from sidebar + scheduling/calendar "Switch to dispatch" CTA
New components (concept-dependent): DispatchBoardConceptA.tsx (tech-day grid) · DispatchBoardConceptB.tsx (day-strip) · DispatchBoardConceptC.tsx (map-first) — pick one for 1.34
Shared infra: UnscheduledWorkOrderRail.tsx · useDispatchDragDrop.ts (dnd-kit hook) · useDispatchEvents Apollo hook
API surface: GraphQL — extend scheduledEvents with technicianId / geoCoords / capacityHours · new assignWorkOrderToTechnician mutation

All three concepts share the same data model — only the UI differs. We can prototype any of them on top of WO-9 with no schema change. The concept choice is a UX bet about which user persona (high-volume service-co dispatcher vs project foreman vs geo-dispersed plumbing/HVAC) we optimise for first.

3. Key decisions for Emma + Corey to discuss

D1 Which concept ships first in 1.34?
Recommended: Concept B (Day-Strip Timeline). Cleanest read for both service and project users, lightest implementation (~8-10d vs A's ~12d / C's ~14-16d), familiar pattern. Concept A becomes a future toggle for service-only customers (Thermogenics-class). Concept C is a 1.35 add-on "Map view" any concept can switch to.
D2 Drag-to-reschedule semantics?
Recommended: Optimistic UI + server reconciliation, undo via toast. Block immediately moves on drop; mutation fires async; if it fails the block snaps back and toast says "couldn't reschedule — <reason>". Standard pattern in the @useanzen/ui base.
D3 Capacity overlay (% utilised per tech per day)?
Recommended: Yes — all 3 concepts. Render as a thin bar under each tech's name (or a percentage in B). Capacity is computed from sum(scheduledHours) / contractedDailyHours. Overtime threshold turns the bar amber.
D4 Customer-facing arrival window?
Recommended: Post-V2. Ties more naturally to the TTC track ("we'll arrive between 1-3 PM" notification). Out of scope for the dispatch board itself; the board produces the data, TTC consumes it.
D5 Mobile dispatcher view?
Recommended: Simplified Concept B only. Tablet-first. Long-press a WO → modal "Reassign to" picker. Full grid (A) and map (C) don't fit on a phone-sized viewport.
