Send Invoice via Email

A "Send" button on every bill. One click opens a modal pre-filled with the customer's contact, a templated subject and body, and the invoice PDF already attached. Every send is logged with delivery status. No more "download → switch to Outlook → attach → write → send" choreography.

Customer drivers: Mak, Owens, Rival, all Vanos Effort: 3-4 days · 1 engineer Existing infra: Mailgun + EmailService + PDF pipeline (all live)

1. Why this matters

Sending an invoice today means a five-app dance: open the bill in Appello, hit Download, find the file in your Downloads folder, switch to Outlook, write a new email, attach the PDF, paste in the customer's address, type a body, send, then come back to Appello and manually mark the bill as "Sent." Six switches per invoice, ~300 invoices a month for a shop like Mak.

"Like QuickBooks - it's a one-click thing... if we could do the same thing with Appello, that's huge for us." — Robert Owens, Owens Insulation (May 2025)
"We need direct email integration - send the invoice and letter to the client's email straight from Appello, plus reminder emails." — Mak Surveying (May 5, 2026 commitment call)

Every customer doing T&M billing has asked for this. Q21030-7709 has been sitting in Tech Review (Emma Mann, Vanos project). Closing it now removes the most-shared friction in the AR loop and unlocks TTC-3 (cover letters) and TTC-4 (auto reminders), both of which depend on this send pipeline.

2. Who this is for

  • Billing admins - the same people who use TTC-1. Send is the next click after Generate.
  • Project managers - sometimes review and send the invoice themselves, especially on T&M jobs.
  • Owners / principals - want a "did the customer get it / open it" answer without picking up the phone.
  • Customer-facing contacts (recipients) - they want a clean, branded email with the PDF attached, not a forwarded mess.

3. User stories

Six stories. The first two are the table-stakes "send a bill" path. The rest cover edits, attachments, audit, and resend.

As a billing admin
I want to email an invoice directly from the bill page, with the PDF auto-attached, so I never leave Appello to send a bill.
As a billing admin
I want the recipient pre-filled from the Job's primary billing contact, so I don't have to look up email addresses every time.
As a billing admin
I want to edit the subject and body before sending and add CC/BCC, so I can write a one-off note when needed.
As a project manager
I want to attach extra documents (signed delivery slips, photos) from the job's Documents tab, so the customer gets everything in one email.
As a billing admin
I want to see a send history per bill (who sent it, when, to whom, did it deliver/open), so I can answer "did they get it?" without calling.
As an owner
I want to resend an invoice with one click if a customer says "I lost it," so I don't recreate the email from scratch.

4. A day in the life: today vs. tomorrow

Mary at Mak just finished generating 30 labor bills with TTC-1. Now she has to send each one to the property developer's accountant.

Today (no TTC-2)

  1. Open bill flyout → click Download PDF
  2. Wait for browser to save the file
  3. Switch to Outlook → New Email
  4. Type recipient address from memory or look up in HubSpot
  5. Type subject "Invoice INV-1042 - April Survey Work"
  6. Type body, paste boilerplate signature
  7. Drag the PDF in from Downloads
  8. Send
  9. Switch back to Appello → mark bill as "Sent" manually
  10. Repeat 29 more times
~3 min per bill · ~90 min for the batch

Tomorrow (with TTC-2)

  1. Open bill flyout → click Send
  2. Modal opens with To, Subject, Body, PDF attached
  3. Confirm or tweak → click Send
  4. Bill auto-flips to "Sent" status
  5. Repeat 29 more times
~15 sec per bill · ~8 min for the batch

6. What's in / out of scope

✓ In scope (v1)

  • Send button on the bill flyout (and on the bill list row's overflow menu)
  • Send modal: To / CC / BCC / Subject / Body (TipTap) / Attachments
  • Recipient pre-fill from Job's primary billing contact + secondary contacts
  • From-address: instance-default (Mailgun) with reply-to set to the sender
  • Auto-attached invoice PDF (rendered fresh at send time)
  • Optional cover letter (driven by TTC-3, can be skipped if no template configured)
  • Add additional attachments from the job's Documents tab (multi-select)
  • Auto-flip bill status from Draft → Sent on successful send
  • Per-bill Send Activity panel (sends + delivery + opens + bounces)
  • Resend (clones last send with editable recipient/body)
  • Mailgun webhook ingestion for delivery / bounce / open events

✗ Out of scope (later)

  • Send-as-user via per-user SMTP / OAuth (Rival's eventual ask)
  • Bulk send across multiple bills in one operation (TTC-4-adjacent)
  • Auto-send on bill creation (TTC-4 reminder schedules cover this)
  • Customer reply threading inside Appello (CRM territory)
  • Rich activity log on Company / Contact records (Rival's CRM ask, separate spec)
  • SMS reminders
  • Read receipts beyond Mailgun's "open" event

7. Decisions needed

D1 · From-address strategy
Three options: (a) generic noreply@instance.useappello.com Mailgun-default; (b) per-instance branded sender with reply-to set to the user; (c) full SMTP-as-user via OAuth. Recommend (b) for v1 — looks branded, replies go to the right human, no per-user setup. (c) is a follow-up.
D2 · Auto-mark bill as "Sent" on successful send?
Recommend yes. Drops a manual step. If a customer needs to keep a sent bill in "Draft" (rare), they can set status manually after.
D3 · Cover letter — required, optional, or off by default?
Recommend optional with smart default: if the customer has a cover letter template assigned (per TTC-3), use it; otherwise no cover letter, just the invoice PDF.
D4 · Permission model
Reuse jobBill.send (new permission). Default ON for users with jobBill.edit. Keeps it simple.
D5 · Mailgun webhook ingestion path
Existing infra has Mailgun webhooks for HR signed docs. Reuse the same webhook receiver pattern — just route jobBill events to a new handler.

8. Acceptance criteria (the QA list)

  1. "Send" button appears on the bill flyout for users with jobBill.send.
  2. Clicking Send opens a modal with To pre-filled from the Job's primary billing contact.
  3. Subject defaults to "[Instance Name] — Invoice [#] ([period])"; user can edit.
  4. Body defaults to a sensible boilerplate (or to the cover letter template if one is assigned per TTC-3); user can edit in TipTap.
  5. Invoice PDF is freshly rendered at send time and attached automatically — never stale.
  6. "Add document from this job" lets the user multi-select additional attachments from the Job's Documents tab.
  7. Send button is disabled if To is empty or no PDF attached.
  8. On successful send, the modal closes and the bill status flips to Sent.
  9. A Send Activity entry is added to the bill flyout immediately, in "Queued" state.
  10. Mailgun webhook events update the activity entry to Delivered / Opened / Bounced as they arrive.
  11. On Bounce, a banner appears on the bill flyout with a Resend action.
  12. Resend pre-fills the modal with the last-sent recipient/body so the user can correct and re-send.
  13. Send history is per-bill and never deleted (audit trail).
  14. Permission denial returns a clear error in the GraphQL response, not a silent fail.
  15. If Mailgun is down, the send is queued and retried; the activity shows "Pending retry."

Engineering notes

Data model

One new model for the audit trail. JobBill gets a derived "lastSentAt" via the relation, no scalar denormalization needed.

model JobBillEmailRecord {
  id                  String       @id @db.VarChar(21)
  isDeleted           Boolean      @default(false)
  createdAt           DateTime     @default(now())
  updatedAt           DateTime     @updatedAt

  jobBillId           String       @db.VarChar(21)
  JobBill             JobBill      @relation(fields: [jobBillId], references: [id], onDelete: Cascade)

  sentByUserId        String       @db.VarChar(21)
  SentByUser          User         @relation(fields: [sentByUserId], references: [id])

  toAddresses         Json         // [{ name, address }, ...]
  ccAddresses         Json?
  bccAddresses        Json?
  subject             String       @db.VarChar(500)
  bodyHtml            String       @db.LongText
  attachmentNames     Json         // ["INV-1042.pdf", "Cover-Letter.pdf"]
  coverLetterTemplateId String?    @db.VarChar(21)

  mailgunMessageId    String?      @db.VarChar(255)
  status              JobBillEmailStatus @default(QUEUED)  // QUEUED, DELIVERED, OPENED, BOUNCED, FAILED
  deliveredAt         DateTime?
  openedAt            DateTime?
  bouncedAt           DateTime?
  bounceReason        String?      @db.VarChar(500)

  @@index([jobBillId])
  @@index([mailgunMessageId])
}

enum JobBillEmailStatus { QUEUED DELIVERED OPENED BOUNCED FAILED }

API surface

OpTypePurpose
sendJobBillMutationSends the bill. Validates inputs, renders fresh PDF, calls EmailService, creates the JobBillEmailRecord, optionally flips status to Sent.
jobBillSendPreviewQueryReturns the prefilled To / Subject / Body for the modal (uses TTC-3 template if one assigned).
JobBill.EmailRecordsFieldSend activity list, ordered desc by createdAt.
JobBill.lastSentAtFieldResolver-level derived field for the bill list status pill.
POST /api/webhooks/mailgun/jobBillRESTWebhook receiver. Updates JobBillEmailRecord by mailgunMessageId on delivered / opened / bounced.

Model methods (in apps/api/src/models/JobBill.ts)

  • sendJobBill(input, userId) — validates permission, renders PDF via existing pdf-export, calls new EmailService(user).sendEmail(...) with attachments, creates the record, optionally calls editItem to flip status. Wraps in transaction with rollback if Mailgun call throws.
  • resolvePrefilledSendInputs(jobBillId, userId) — reads job + customer + assigned cover letter template, returns { to, cc, subject, body, coverLetterTemplateId }.
  • handleMailgunWebhook(event) — webhook router; updates the record by mailgunMessageId.

Frontend touch points

  • BillDetails.tsx — add "Send" button to the flyout header toolbar, and a "Send activity" panel below the bill body.
  • SendInvoiceModal.tsx (new) — the send modal. Uses useLazyQuery(jobBillSendPreview) on open and useMutation(sendJobBill) on submit. TipTap editor reuses the existing notes editor pattern.
  • JobBillStatusDropdown.tsx — reads lastSentAt for the "Sent" badge.
  • JobBillList.tsx — list row's overflow menu gets a "Send" item.

Mailgun integration reuse

The existing EmailService at apps/api/src/lib/emailService.ts already supports multipart with attachments (used by HR's SignedDocumentEmailer + UserCertification). No new infrastructure — TTC-2 is just a new caller.

Permissions

  • New permission key: jobBill.send. Default ON for any user with jobBill.edit.
  • Webhook endpoint validates Mailgun signature; no auth otherwise (Mailgun's standard flow).
