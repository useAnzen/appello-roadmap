Mobile WO Edit · Stepped Form (Free Navigation)

Today the mobile WO edit flow is a single flat form — techs scroll a long page to change one field. Mirrors the WO-8a stepped create wizard for the edit flow so techs land in a familiar interface. Key delta vs create: the WO already exists with required fields satisfied, so step navigation is free — every step dot is tappable, no sequential gating, no "Next-then-Save" forced flow. User can jump straight to the section they want to edit. Path B build of WOX-07; closes one of Emma's three loose threads under scope #8.

Estimate: 1-1.5 days Sequence: 1.33, after WO-8a Requires: WO-8a, WO-3 Enables: Closes Emma's #8 loose thread (mobile edit step-by-step)

1. Business Case

Mobile WO create uses a 5-step wizard (per WO-8a) — sectioned, step-by-step, with a Summary step at the end. Mobile WO edit today is a flat form: every section rendered in one long page, the user scrolls to find what they want to change. Two related complaints from techs in the field:

  • "Looking at the form again after creation feels totally different from when I made it" — context-switch friction. The wizard is the mental model techs already have for what's on a WO.
  • "I have to scroll past 8 sections to fix one field" — the flat form punishes precise edits.

Reuse the existing wizard for edit. Almost everything stays the same — step indicator, section rendering, Summary step, DataModelForm wiring — because the data model is the same data model. The one meaningful behavior difference: edit doesn't need a sequential walk. Required fields were already filled at create time; the user wants to dive straight to "Materials" or "Customer Info" and change one thing. Free step navigation respects that.

2. Scope

Already Built

  • DONE WO-8a Stepped Form Wizard — step indicator component, step rendering logic, Summary step, DataModelForm with the steppedForm prop
  • DONE Existing mobile WO edit form (flat) — host that gets replaced by the stepped variant
  • DONE WO detail page on mobile (tapping "Edit" or a section navigates here)

In Scope (WO-21)

  • IN Replace the flat mobile WO edit form with the stepped wizard from WO-8a — same visual, same step indicator, same Summary step
  • IN Extend the DataModelForm steppedForm prop with a free-navigation mode (e.g., steppedFormMode: "sequential" | "free" or a sibling boolean). In free mode: every step dot is tappable from any state; the "Next" button optional but not required.
  • IN Visual cue on step dots in free mode — pending dots render as tappable (blue outline) rather than greyed out, signaling jumpability
  • IN Save button visible on every step (not just Summary) — user can save from any step after editing. Save validates required fields across all sections (not just the visible step).
  • IN Required-field validation behavior on edit: same rules as create (required is required), but enforcement moves from "Next gate" to "Save gate." If a required field has been emptied during this edit session, save fails with a clear message pointing the user back to the offending step.
  • IN Entry points from mobile WO detail page: tapping "Edit" lands on Step 1; tapping a specific section header on the detail page deep-links into that section's step
  • IN Summary step still rendered as the last step; useful for "review everything" before save, even though save is reachable from any step

Out of Scope

  • OUT Schema changes — none. The data model is identical to create.
  • OUT The step indicator component itself, step rendering logic, section field rendering, Summary step layout — all defined in WO-8a and reused 1:1
  • OUT Sequential-mode change for create — create stays sequential (forces required-field flow); only edit uses free mode
  • OUT Desktop WO edit form — desktop has its own create/edit form (WO-3); this spec is mobile-only
  • OUT Per-section "Save" buttons that commit only that section — single Save commits the whole form (matches create behavior)
  • FUTURE Per-step optimistic save (autosave on step change) — promote later if techs report data loss from forgetting to save

4. Data Model

No schema changes. Edit operates on the same data model as create. The wizard reuses DataModelForm's existing field rendering and validation logic.

5. API Surface

No new GraphQL types, queries, or mutations. Save flows through the existing WO edit mutation (same as the flat form does today). The change is purely in the rendering layer.

5.1 DataModelForm prop extension

<DataModelForm
  steppedForm={true}                      // existing prop from WO-8a
  steppedFormMode="free"                  // NEW: "sequential" (create) | "free" (edit)
  initialStep={deepLinkSectionStep ?? 0}  // NEW: optional initial step index for deep-linking
  saveOnEveryStep={true}                  // NEW: when true, Save button visible on every step
  ...
/>

steppedFormMode defaults to "sequential" to preserve WO-8a create behavior. Edit-flow callers pass "free". initialStep lets the WO detail page navigate directly into a specific section's step.

7. Acceptance Criteria

  1. The mobile WO edit form renders as a stepped wizard visually identical to WO-8a's create wizard (same step indicator, same section rendering, same Summary step).
  2. Tapping the "Edit" button on the WO detail page mobile lands the user on Step 1 of the wizard.
  3. Tapping a section header on the WO detail page mobile deep-links the user directly into that section's step.
  4. In edit (free-navigation) mode, every step dot in the indicator is tappable from any state, including dots representing steps the user hasn't visited yet.
  5. Pending step dots in free mode render with a tappable visual treatment (blue outline) distinct from sequential mode's greyed-out treatment.
  6. The Save button is visible on every step's action bar (not only the Summary step).
  7. Tapping Save from any step validates required fields across all sections; on validation failure, the error message identifies the offending step and tapping the message jumps to it.
  8. The Next and Previous buttons remain present and functional but are optional — the wizard does not require sequential traversal in free mode.
  9. The Summary step remains the last step in the indicator and renders the same overview layout as create's Summary step.
  10. Sequential-mode behavior on create (WO-8a) is unchanged — required-field gating on Next, Save only on Summary.
  11. The data submitted on Save is identical in shape to what the flat form submits today; the existing edit mutation is reused without changes.
  12. No schema changes; only the DataModelForm prop surface gains three new optional props (steppedFormMode, initialStep, saveOnEveryStep).
