AI Voice-to-Report (Mobile Field Capture)

A tech in the field hits a mic button on the WO mobile screen, talks for 30 seconds about what they did, and AI structures it into a WO update — labor hours, materials used, photos, signoffs, follow-up tasks. Replaces typing on a tiny screen with hands-free dictation.

Status: Concept · Deferred Effort: ~6-8d · 1.34 Extends: WO-8 · WOX-08 Master ref: #38

1. Where this lives in the app

Page / route: apps/mobile/src/pages/workOrders/[id].tsx (path TBD — V1 builds it per WO-8)
Components touched: WO mobile detail layout (path TBD), apps/mobile/src/components/Forms/_FormControls/FormControl.tsx for the confirm screen
New components: <VoiceReportFAB />, <VoiceRecordingModal />, <VoiceReportConfirm /> (path TBD)
API surface: GraphQL — startVoiceReportSession, submitVoiceReportAudio, applyVoiceReportExtraction; new model VoiceReportSession

The mobile WO detail screen (built in V1 via WO-8) gets a floating green mic FAB pinned bottom-right above the existing action bar. Tapping it opens a full-screen recording modal that captures up to 90 seconds of audio. On stop, the audio uploads to a new service that calls Whisper for transcription, then GPT-4 with strict tool-calling for structured extraction against the WO schema.

The extracted structure is diff'd against the current WO and shown to the tech on a confirmation screen — every field has a checkbox to apply or skip. Nothing is auto-saved; the tech taps "Apply" to commit. All raw audio + transcripts + diffs are persisted on the VoiceReportSession row for audit and re-run.

2. UI Concept

Three mobile screens in the voice-to-report flow: idle (mic FAB on WO detail), recording (waveform + cancel), and confirm (diff'd structure with per-row checkboxes).

3. Key decisions for Emma + Corey to discuss

D1 Which transcription provider?
Recommended: OpenAI Whisper API. Best accuracy on construction/trades vocabulary, handles French + English natively, Canadian-friendly pricing (~$0.006/min). Stream-friendly enough for the 30-90s clips this flow expects.
D2 Which LLM for structured extraction?
Recommended: GPT-4o mini with strict tool-calling. Schema-validated tool calls eliminate JSON parsing errors, ~10× cheaper than full GPT-4, and the 200ms latency is well below tech patience. Fall back to GPT-4o full only if mini fails schema validation.
D3 Offline support?
Recommended: Yes — capture audio offline to local device storage, queue + transcribe when online. Critical for field techs in mechanical rooms, basements, rural sites with no signal. Aligns with the existing offline-first patterns in the mobile app.
D4 Confirm gate vs auto-apply?
Recommended: Always confirm — never auto-apply structured data to a WO. Voice + LLM is a confidence ~0.85 signal, and silent edits to billable hours / materials would erode trust fast. Cheap UX cost (one tap), huge trust dividend.
D5 Multi-language?
Recommended: English + French in V1 (Whisper handles both natively, our QC instances need French). Spanish queued for 1.35+ once we have a Spanish-speaking customer. Auto-detect language from the audio rather than asking the tech to pick.
