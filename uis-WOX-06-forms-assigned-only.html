Forms on WOs — Assigned-Only Visibility

Forms attached to a WO (HIRA, gas-pressure check, customer signoff) appear on mobile only for the user assigned to that WO/visit — not the entire crew. Admins still see all. Reduces a tech's mobile inbox from 7 forms down to the 2 that are actually theirs.

Status: Concept Effort: +1d on WO-8 Extends: WO-8 · F-09 Master ref: #18

1. Where this lives in the app

Mobile WO detail: mobile WO detail screen (path TBD — verify, will live under apps/mobile/src/pages/admin/work-orders/[id]/ when shipped); inbox filter logic in mobile Forms inbox
Mobile Forms inbox: existing uis-F05-form-inbox.html surface — filter respects visibilityScope
Admin form-on-template config: WO Template builder (per WOX-02) — new visibilityScope dropdown per attached form
Desktop: apps/frontend/src/pages/jobs/[id]/index.tsx — admins see all forms regardless of scope
API surface: GraphQL — new WorkOrderForm.visibilityScope: ASSIGNED_USER_ONLY | ALL_CREW enum on the existing form-attachment record (form-assignment plumbing already exists on jobs per master plan)

This is purely a UI surface + filter. The form-attachment plumbing already exists on jobs. We add a visibilityScope field to the WO-form attachment record, then the mobile Forms inbox filters out forms whose scope is ASSIGNED_USER_ONLY when the current user is not in WorkOrderAssignee for the relevant visit's date.

3. Key decisions for Emma + Corey to discuss

D1 Default visibility scope?
Recommended: ASSIGNED_USER_ONLY for newly attached forms; ALL_CREW for forms attached on existing WOs (back-compat). Migrations preserve current "everyone sees everything" behavior; new attaches default to the cleaner UX.
D2 Admin override per-WO (not just per-template)?
Recommended: Yes — last-mile flexibility. Each form attached to a specific WO can override the template default (e.g., emergency call-out where the dispatcher wants the whole crew to fill HIRA). Field stays on the attachment record, not the form definition.
D3 Desktop visibility for admins?
Recommended: Admins see all forms on the WO regardless of scope, with a small "Hidden from techs" tag on assigned-only forms. Mobile field UX gets the filtering; desktop stays full-fidelity for oversight.
D4 Which roles count as "assigned"?
Recommended: Any user appearing in WorkOrderAssignee for that visit's date. Multi-day WOs filter per-date — Sarah's customer-signoff form only appears on the day she's scheduled. Pairs cleanly with the multi-day UX polish (item #21).
D5 What about "any of these roles"-type assignment (e.g., gas-fitter only)?
Recommended: Defer to post-V1 (item #37 — checklist user/role assignment) and treat forms identically. V1 is binary (assigned-user-only vs all-crew); role-based scoping ships in V2.
